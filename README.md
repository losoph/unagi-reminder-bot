# Unagi Reminder Bot

Telegram-бот для отложенных напоминаний и дайджестов по Telegram-каналам.

**Документация:** [устройство системы](docs/architecture.md) ·
[дорожная карта](docs/roadmap.md) · [текущий спринт](docs/sprint/) ·
[исследования](docs/research/)

## Возможности

- **Напоминания**: пересланное сообщение → отложить; быстрый перенос кнопками (утро/день/вечер, +1 ч, +3 ч, дата), на доставленном — в один тап (+3 ч, вечером, завтра утром) или ответом на напоминание текстом: «завтра 11», «24/09 в 9», «через 2 дня», «в пятницу в 10» (также `/morning`, `/day`, `/evening`, `/later`, `/at`).
- **Меню и справка**: `/start` — главное меню кнопками, `/help` — полная справка по всем командам, `/settings` — все настройки, `/cancel` — сбросить текущее действие.
- **База знаний (закладки)**: теги-папки, страницы, перенос между категориями, превращение в напоминание.
- **Дайджесты публичных каналов**: подписка пересылкой поста или ссылкой на канал (`t.me/канал`, `t.me/s/канал`, ссылка на пост, `telegram.me`, `tg://resolve`, `@канал`), периодичность daily/weekly/monthly с настройкой времени.
  - **Один выпуск в день**: если ежедневный совпал с еженедельным или ежемесячным, приходит одно общее сообщение во время старшего, посты за сутки — первой группой.
  - Группировка подписок по папкам, маркеры статуса (⏸ пауза / ⚠️ ошибка чтения).
  - Пауза/возобновление как по одному каналу, так и массово; отписаться от всех.
  - Большие дайджесты (по умолчанию 4+ постов) публикуются в **Telegraph** одной ссылкой.
  - `/check` — проверка доступности всех каналов.
  - `/email` — дайджесты на почту (адрес подтверждается кодом; вёрстка как в Telegraph). Для каждого типа — ежедневный/еженедельный/ежемесячный — выбирается **либо** почта, **либо** Telegram; при переключении бот предупреждает. Не ушедшее письмо дублируется в Telegram; отписка ссылкой из письма возвращает всё в Telegram. Под каждым каналом в письме — «Отписаться» и «Перенести» в другой выпуск (ссылки открывают бота).
- **Анализ каналов (DeepSeek)**: по каждому каналу — частота постинга, оценка времени чтения, рекомендация по периодичности дайджеста и саммари постов за 30 дней. Вопросы заготовленные (кнопки), без свободного ввода. Работает при заданном `DEEPSEEK_API_KEY`; без него остаётся расчётная часть (частота/время чтения).
- **Лента**: `/feed` — единая ранжированная подборка до 50 постов из выбранных каналов за **день**, **неделю** или **месяц**. Выпуск публикуется только на публичной странице в **Telegraph** (в чат приходит короткое сообщение со ссылкой); при желании можно включить автодоставку по расписанию дайджеста.
  - Каналы добавляются вручную: пересылкой поста в чат бота (кнопка «📰 В Ленту»), отправкой ссылки на канал или из списка подписок дайджеста.
  - Для владельца MTProto-сессии доступен быстрый подбор каналов из своих личных подписок («➕ Из моих подписок»).
  - Тематические разделы: подписке можно задать тег — посты на странице Telegraph группируются по разделам (сначала каналы без тега, затем теги по алфавиту).
  - В отличие от дайджеста, у подписки Ленты нет фиксированного расписания — выпуск формируется по запросу за выбранный период (скользящее окно).
- **Экспорт/импорт (JSON)**: `/export` выгружает напоминания, закладки, подписки дайджеста, каналы Ленты и настройки; `/import` восстанавливает их из присланного JSON-файла.

## Требования

- Python 3.12+
- Telegram bot token

## Локальный запуск

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
mkdir -p storage
python main.py
```

Если использовать `.env.example` без изменений, SQLite-файл будет создан в `storage/bot_data.db`.
Если `DB_PATH` не задан, приложение использует путь по умолчанию `bot_data.db` в корне проекта.

## Переменные окружения

- `BOT_TOKEN` - токен Telegram-бота, обязателен
- `APP_TIMEZONE` - часовой пояс приложения, по умолчанию `Europe/Moscow`
- `DB_PATH` - путь к SQLite-файлу
- `MESSAGE_RETENTION_DAYS` - срок хранения обработанных напоминаний
- `SUBSCRIPTION_FAILURE_RETENTION_DAYS` - срок хранения permanently failed подписок
- `DIGEST_POST_RETENTION_DAYS` - срок хранения постов в базе знаний для ИИ-анализа (по умолчанию 30)
- `MAX_ERROR_TEXT_LENGTH` - лимит сохраненного текста ошибки
- `DIGEST_TELEGRAPH_THRESHOLD` - с какого числа постов дайджест публикуется в Telegraph (по умолчанию 4)
- `TELEGRAPH_TOKEN` - необязательный токен Telegraph (иначе создаётся автоматически)
- `DEEPSEEK_API_KEY` - ключ DeepSeek; без него ИИ-функции отключены
- `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURITY` (`starttls`/`ssl`/`none`), `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM` - переопределения SMTP для email-дайджестов. По умолчанию всё берётся из msmtp-конфига алертов `/root/.msmtprc`, который docker-compose монтирует read-only в `MSMTPRC_PATH` (`/run/secrets/msmtprc`)
- `DEEPSEEK_BASE_URL` - базовый URL API DeepSeek (по умолчанию `https://api.deepseek.com`)
- `DEEPSEEK_MODEL` - модель DeepSeek (по умолчанию `deepseek-chat`)
- `AI_DAILY_LIMIT` - лимит ИИ-запросов в сутки на пользователя (0 = без лимита)
- `FEED_AI_SUMMARY` - включает необязательный ИИ-обзор «Главное за период» на странице Ленты (`on` по умолчанию, `off` — выключить)
- `FEED_AI_TIMEOUT_SECONDS` - предельное время ожидания ИИ-обзора Ленты (по умолчанию 20 секунд); при ошибке или таймауте страница публикуется без обзора
- `MAX_IMPORT_SUBSCRIPTIONS` / `MAX_IMPORT_BOOKMARKS` / `MAX_IMPORT_REMINDERS` / `MAX_IMPORT_FILE_BYTES` - лимиты импорта JSON
- `CHANNEL_SOURCE` - источник контента: `auto` (по умолчанию), `mtproto` или `web`
- `TELEGRAM_API_ID` / `TELEGRAM_API_HASH` / `TELEGRAM_USER_SESSION` - реквизиты пользовательской MTProto-сессии; при их наличии каналы читаются нативно
- `MTPROTO_WEB_FALLBACK` - разрешить fallback на веб-просмотр при ошибке MTProto
- `MTPROTO_FETCH_LIMIT` - защитный лимит сообщений за одну синхронизацию канала
- `DIGEST_DUE_BATCH_SIZE` - максимум due-подписок за один цикл (по умолчанию 100); старейшие обрабатываются первыми
- `DIGEST_BACKLOG_RETRY_SECONDS` - пауза перед следующим batch, если due-очередь ещё не пуста (по умолчанию 5 секунд)
- `TELEGRAM_PREVIEW_CHARS` - максимальная длина текста поста в превью Telegram-сообщения (по умолчанию 300)
- `TELEGRAPH_POST_CHARS` - максимальная длина текста одного поста на странице Telegraph (по умолчанию 1500)
- `PRIORITIZE_THRESHOLD_PER_DAY` - порог частоты публикаций канала (постов/день), выше которого включается алгоритм ранжирования (по умолчанию 20)
- `MAX_POSTS_PER_CHANNEL` - лимит постов из одного активного канала в выпуске (по умолчанию 5)
- `FORWARD_STANDOUT_RATIO` - множитель форвардов к медиане канала для обязательного включения поста сверх лимита (по умолчанию 1.25)
- `FORWARD_STANDOUT_MAX_EXTRA` - максимум дополнительных постов с высоким числом форвардов на канал за выпуск (по умолчанию 3)
- `WEB_FETCH_MAX_PAGES` - максимальное число страниц при постраничной загрузке веб-fallback через `?before=` (по умолчанию 15)
- `BOT_CPUS` - лимит ядер CPU для Docker-контейнера в compose (по умолчанию `1.0` под 1 vCPU хост)
- `WEB_FETCH_PAGE_DELAY` - задержка в секундах между постраничными запросами веб-fallback (по умолчанию 0.5)

Каналы читаются нативно через MTProto (Telethon) поверх OpenVPN-туннеля; веб-парсинг `t.me/s` —
только резервный путь. Подробнее об источниках, курсорах, планировщике и ранжировании —
в [docs/architecture.md](docs/architecture.md).

Строку пользовательской session создавайте только в доверенном терминале:

```bash
python scripts/generate_mtproto_session.py
```

Полученное значение является секретом уровня аккаунта и должно храниться как
`TELEGRAM_USER_SESSION`, а не в репозитории.

## Запуск на VDS

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
mkdir -p storage
python main.py
```

Для systemd в качестве рабочей директории используй каталог проекта, чтобы `python main.py` корректно находил модуль `data.database`.

Пример `ExecStart`:

```ini
ExecStart=/opt/unagi-reminder-bot/.venv/bin/python /opt/unagi-reminder-bot/main.py
WorkingDirectory=/opt/unagi-reminder-bot
```

## Запуск в Docker

```bash
cp .env.example .env
docker compose up --build -d
```

Контейнер ужесточён (hardened):
- Запуск от непривилегированного пользователя `bot` (`uid 10001`, `gid 10001`), права root сбрасываются точкой входа через `setpriv`;
- Сброшены все capabilities (`cap_drop: ALL`), включён `no-new-privileges: true`;
- Корневая файловая система только для чтения (`read_only: true`), временные каталоги `/tmp` и `/run/unagi` — в `tmpfs`;
- Лимит CPU по умолчанию ограничен 1.0 (`BOT_CPUS=1.0`), так как прод имеет 1 vCPU;
- База хранится в `/app/storage/bot_data.db` (права 0600, владелец 10001:10001);
- Перед каждым деплоем в CI создаётся консистентный снимок БД (`ops/aiqu/backup_db.py`) со сжатием старых копий в gzip (`.db.gz`, BK1).
