КОНТЕКСТ. На проде в docker-compose.yml вручную стоит `cpus: 1.0` (в репозитории 1.5). Из-за этого деплой идёт с `git pull --autostash`, а конфликт при возврате stash оставит маркеры в compose и остановит деплой (отмечено двумя независимыми сверками). Лечение — вынести значение в переменную окружения, чтобы правка на сервере жила в `.env`, а compose был чистым.
Кроме того, для двух открытых решений владельца нужны цифры из прод-БД, но читать прод можно только проверенным скриптом ops/aiqu/prod_check.sh (ad hoc ssh заблокирован политикой): (1) сколько напоминаний за 30 дней не доставлено окончательно — обоснование (не)нужности резервной доставки в MAX; (2) сколько каналов состоят у одного пользователя больше чем в одном теге или периоде — размер конфликтов будущей миграции очереди 4.

ЧТО СДЕЛАТЬ.
1. docker-compose.yml: `cpus: ${BOT_CPUS:-1.5}` (интерполяция берётся из .env рядом с compose; значение по умолчанию 1.5 как сейчас). В .env.example — закомментированная строка `# BOT_CPUS=1.5` с пояснением «на проде 1.0». Существующий тест tests/test_container_hardening.py должен остаться зелёным (поправь его только если он прямо зависит от строки cpus).

Порогов и ALERT/WARN для этих цифр НЕ вводить. Секреты и значения .env не печатать. bash -n должен проходить.

Даты относительные.
