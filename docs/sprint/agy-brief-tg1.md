КОНТЕКСТ. Дайджест публикуется в Telegraph, когда в выпуске ≥ DIGEST_TELEGRAPH_THRESHOLD (4) постов: main.py (около строки 1137) вызывает `publish_digest(title, sections)`, а страницу строит `telegraph_publisher.build_content(sections, *, with_actions=False)`.
Тот же `build_content(..., with_actions=True)` использует email_digest.py (строка ~172, `render_nodes`) — письмо не должно сломаться. Сейчас формат: блок «что внутри» (счётчики, список «канал — N»), затем для каждого канала `h4`-заголовок, посты подряд в виде
«🔹 **первое предложение** остальное Читать» (до 1500 символов на пост), «▫️ ещё N постов в канале» и `hr` после каждого канала. На 20+ постах это сплошная простыня: заголовки не отделены от текста, длинные посты съедают страницу, пользователь не видит главного.
Образец нужного уровня читаемости — Лента v3: `feed_render.py` и `docs/sprint/lenta-v3-sample.txt` (заголовок → суть → подпись → метрики, «Коротко» для остальных, без повторов каналов, оглавление).

ЦЕЛЬ. Для выпуска из 20+ постов 5–10 каналов страница читается сверху вниз за минуты и позволяет выхватить главное:
1. Вводная строка (сколько каналов/постов, ≈ минут чтения — как сейчас) и компактное ОГЛАВЛЕНИЕ по каналам (канал — N постов). Если ссылки-якоря внутри страницы Telegraph не работают — оглавление остаётся простым списком, не изобретай обходы; проверь по документации API Telegraph в коде, сеть не используй.
2. Внутри канала: самые содержательные посты (до 3 на канал; выбор — детерминированный: длина «сути», наличие ссылки; без ИИ) — карточкой: заголовок жирным (ссылка «Читать» на пост), под ним «суть» одной-двумя строками. Остальные посты канала — одной строкой «Коротко» (заголовок-ссылка). Название канала НЕ повторяется в каждой строке (оно в h4 над блоком).
3. Заголовок/суть извлекать готовыми функциями из feed_render.py (импортировать, не копировать и не менять их): `_clean_post_text`, `_extract_title_and_essence`, `_normalize_caps_title`, `_truncate_by_word` — они уже убирают служебные строки, цепочки эмодзи, КАПС, обрезку по слову. Заголовки не должны обрываться на полуслове; «суть» не повторяет заголовок.
4. Группы (`section["group"]`, h3) и порядок каналов сохранить; `omitted_count` («▫️ ещё N постов в канале») сохранить; `with_actions` и `section["actions"]` (отписаться/перенести) работают как раньше.
5. Размер: страница ≤ 60 000 байт (`_MAX_CONTENT_BYTES`). Существующее усечение `_truncate_to_limit` и предупреждение «⚠️ Выпуск усечён» должны продолжать работать с новым форматом; `_is_post_node` опирается на маркеры узлов поста — приведи его в соответствие.
6. Публичный контракт не менять: сигнатуры `build_content`, `publish_digest`, `describe_counts`, `plural_ru`. Без медиа и картинок; только Telegraph-узлы (p, b, a, h3, h4, ul, li, hr, blockquote — проверь, какие теги умеет email_digest.render_nodes, и не вводи новых без необходимости).
