# OPS3 — надёжность деплоя и завершения по критике Argon (18.10)

Контекст: деплой — .github/workflows/deploy.yml (ssh-action под root, set -e; блоки `# --- sync` и `# --- liveness` исполняются тестами tests/test_deploy_sync.py и tests/test_dep2_deploy_verify.py во временной среде — сохраняй маркеры блоков и расширяй эти тесты). Бот в контейнере uid 10001, restart: unless-stopped, SQLite WAL, `get_connection()` открывает соединение на каждый вызов. Метка версии org.unagi.git_sha ставится на КОНТЕЙНЕР в docker-compose.yml из ${GIT_SHA} (Dockerfile не трогать ради метки).

Сделай (каждый пункт — с регрессионным тестом):
1. Откатный тег: обновлять `unagi-reminder-bot-bot:rollback` только если текущий контейнер здоров (State.Status=running и RestartCount=0); иначе оставить прежний тег. Сценарий: деплой упал на liveness, следующий деплой не должен затереть рабочий образ сломанным.
2. Автооткат: при провале liveness перед `exit 1` поднять контейнер из `:rollback` (если тег есть), напечатать, что сделан откат, и всё равно завершиться с ошибкой (job красный). Вынеси в маленький блок с маркерами `# --- rollback` и протестируй фейковым docker.
3. Готовность вместо `sleep 20`: опрос каждые 2 с до DEPLOY_WAIT_SECS (по умолчанию 60): контейнер running, метка совпадает, и RestartCount не растёт в течение последних 10 с. Ложный провал при одном быстром перезапуске на старте не нужен: допускается RestartCount ≤ 1, если после него 10 с стабильности. Прикладной маркер готовности (файл /run/unagi/ready, который main.py создаёт после инициализации БД и роутеров) — сделай: main.py пишет его, liveness проверяет `docker exec ... test -f /run/unagi/ready`.
4. Диск до сборки: если df ≥ 85% — `docker builder prune -f` и `docker image prune -f` ДО `docker compose up --build` (сейчас только после).
5. Снимок БД и проверки не от root: backup_db.py в deploy.yml запускать как uid 10001 (`setpriv --reuid=10001 --regid=10001 --clear-groups python3 ...`), чтобы файлы -wal/-shm, созданные при открытии БД, не принадлежали root (иначе бот получает «attempt to write a readonly database»). То же для `sqlite3` в ops/aiqu/prod_check.sh (remote(): `setpriv ... sqlite3 -readonly`). Каталог storage/backups должен быть доступен uid 10001 — проверь entrypoint (ops/docker/entrypoint.sh) и добавь `chown` при необходимости.
6. Корректное завершение: в main.py обработчик остановки (aiogram on_shutdown или SIGTERM): остановить фоновые циклы, дождаться задач, выполнить `PRAGMA wal_checkpoint(TRUNCATE)` и завершиться; в docker-compose.yml `stop_grace_period: 30s`. Тест: функция завершения вызывает чекпоинт (на временной БД).
7. Устаревшие cron-файлы: перед установкой из ops/aiqu/cron.d удалять файлы /etc/cron.d/unagi-*, которых нет в репозитории; в тест (или новый tests/test_cron_files.py) — проверка, что все файлы ops/aiqu/cron.d/* без точки в имени, начинаются с `unagi-` и заканчиваются переводом строки.

НЕ делать: переключение пользователя деплоя (только на новом сервере), изменения network_mode.
