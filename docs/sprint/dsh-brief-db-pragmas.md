ПРОБЛЕМА. `get_connection()` (data/database.py около строки 41) на КАЖДЫЙ вызов (≈118 мест) делает `sqlite3.connect`, 5 PRAGMA и `_secure_db_files()` (os.path.exists + os.chmod для файла БД, -wal, -shm).
`journal_mode=WAL` хранится в самом файле БД и выставлять его на каждом соединении не нужно. `cache_size = -64000` (64 МиБ на соединение) при лимите контейнера 512 МиБ — главный риск OOM.
`cleanup_old_records` (около строки 2863) удаляет всё одной транзакцией с одним commit — write-lock держится всё время, синхронные записи обработчиков ждут `busy_timeout`.

ЦЕЛИ.
1. `journal_mode=WAL` выставлять один раз в `init_db()` (и там же `_secure_db_files()`). На каждом соединении оставить только настройки уровня соединения: `busy_timeout` и `synchronous=NORMAL`;
   `temp_store=MEMORY` оставить, `cache_size` снизить до `-16000` (16 МиБ). Поведение существующих БД не должно меняться: WAL остаётся включённым, файлы остаются с правами 0600 (SEC1 п.6 — тест на права должен остаться зелёным).
   Права: файл БД и спутники закрывает umask 0o077 (строка ~11) + `_secure_db_files()`; не вызывай chmod на каждом соединении — достаточно при `init_db()` и один раз на путь БД за процесс (кеш по строке пути; тесты подменяют `db.DB_PATH`, поэтому ключ — сам путь).
2. `cleanup_old_records` — порциями: для каждой таблицы цикл `DELETE FROM t WHERE rowid IN (SELECT rowid FROM t WHERE <условие> LIMIT ?)` с размером порции `CLEANUP_BATCH_SIZE` (константа, 500) и commit после каждой порции, пока удалено меньше порции.
   (`DELETE ... LIMIT` в сборке SQLite может отсутствовать — только вариант с подзапросом.) Условия, возвращаемый словарь счётчиков и ключи — БЕЗ изменений (счётчики = суммарно удалено по таблице).
3. Заодно (Б8): `add_digest_posts` — `executemany` и одно соединение на вызов вместо `execute` на пост, если это не меняет поведения (дубликаты, возвращаемое значение). Если есть сомнения — не трогай и напиши об этом.
НЕ ТРОГАТЬ: `PRAGMA synchronous` (остаётся NORMAL), WAL, семантику курсоров дайджеста, сигнатуры публичных функций, схему таблиц.
