# Контракт обмена unagi → ghsub: выпуск Telegram-каналов (JSON v1)

**Версия схемы:** `1.0`  
**Статус:** Согласован (18.10.2026)  
**Участники:** [unagi](https://github.com/losoph/unagi-reminder-bot) (источник выпусков) → [ghsub](https://github.com/losoph/ghsub) (почтовый отправитель)  
**Связанные документы:** [ADR-006](adr/ADR-006-email-aggregator-and-server-profile.md), [ADR-007](adr/ADR-007-recipients-and-unagi-intake.md)

---

## 1. Назначение и модель взаимодействия

unagi собирает публикации отслеживаемых Telegram-каналов, ранжирует их по расписаниям пользователей и формирует выпуски (дайджесты и подборки). Для доставки в почту unagi сериализует сформированный выпуск в формат **JSON v1** и передаёт его ghsub через локальный спул-каталог.

ghsub действует как надёжный почтовый приёмник (intake):
1. Валидирует структуру JSON v1 и схему;
2. Проверяет наличие адресата в локальной конфигурации (`recipients`);
3. Дедуплицирует выпуск по ключу идемпотентности `edition_id`;
4. Выполняет безопасный рендеринг письма (HTML + plain text alternative) с группировкой карточек по каналам и блоком «Коротко»;
5. Отправляет письмо через системный транспорт (msmtp / Brevo);
6. Фиксирует статус и раскладывает файлы по подкаталогам (`done/`, `rejected/`).

---

## 2. Транспорт и файловый обмен

- **Спул-каталог по умолчанию:** `/var/lib/tldw/ghsub/unagi-inbox/` (на сервере aiqu).
- **Атомарность записи:** unagi формирует выпуск во временном файле на той же файловой системе (например, `.tmp_edition_<edition_id>.json`) и атомарно переносит его в спул через `rename` / `os.replace` с именем `<edition_id>.json`.
- **Подкаталоги обработки:**
  - `unagi-inbox/done/` — выпуск успешно отправлен адресату, либо пропущен как дубликат, либо помечен как `empty` (пустой выпуск).
  - `unagi-inbox/rejected/` — файл повреждён, не соответствует схеме `1.0` или содержит неизвестного адресата (`recipient`). Причина отклонения пишется в журнал ghsub.
  - При ошибке почтового транспорта (сбой сети, временная ошибка SMTP) файл **остаётся во входящих** и повторяется при следующем запуске обработчика (каждые 5 минут).

## 3. Спецификация полей схемы JSON v1

### Корневой объект

| Поле | Тип | Обязательность | Описание и ограничения |
|---|---|---|---|
| `schema_version` | string | Да | Строго `"1.0"`. |
| `edition_id` | string | Да | Уникальный непустой идентификатор выпуска (ключ идемпотентности). Например, `"tg-digest-20261018-0700-primary"`. |
| `kind` | string | Да | Тип выпуска: `"digest"` (периодический дайджест) или `"feed"` (лента/подборка). |
| `recipient` | string | Да | Символический ключ адресата (например, `"primary"`). Должен присутствовать в секции `recipients` в `/etc/tldw/ghsub.yml`. |
| `title` | string | Да | Заголовок выпуска. Используется как основа темы письма и главного заголовка `<h1>`. |
| `period` | string | Да | Описание периода (например, `"weekly"`, `"daily"` или `"11–18 октября 2026"`). |
| `window` | object | Да | Временные границы выпуска (см. ниже). |
| `telegraph_url` | string \| null | Да | Ссылка на опубликованную версию в Telegraph (или `null`, если отсутствует). |
| `manage_url` | string | Нет | Опциональная ссылка на управление подпиской (например, диалог с ботом unagi). |
| `unsubscribe_url` | string | Нет | Опциональная ссылка на отписку. |
| `items` | array[object] | Да | Список публикаций (может быть пустым `[]`). |

### Объект `window`

| Поле | Тип | Описание |
|---|---|---|
| `from` | string | Дата/время начала окна в формате ISO 8601 (например, `"2026-10-11T00:00:00Z"`). |
| `to` | string | Дата/время конца окна в формате ISO 8601 (например, `"2026-10-18T00:00:00Z"`). |
| `timezone` | string | Имя часового пояса IANA (например, `"Europe/Moscow"`). |

### Элементы массива `items`

Каждый элемент представляет собой публикацию Telegram-канала:

| Поле | Тип | Обязательность | Описание и ограничения |
|---|---|---|---|
| `post_id` | int \| string | Да | Идентификатор сообщения в канале. |
| `published_at` | string | Да | Дата/время публикации в формате ISO 8601. |
| `channel` | object | Да | Объект канала: `{"username": string, "title": string}`. |
| `tier` | string | Да | Уровень отображения: `"card"` (полная карточка) или `"brief"` (краткая заметка в блоке «Коротко»). |
| `title` | string | Да | Заголовок новости / карточки. Экранируется санитайзером. |
| `summary` | string | Да | Текст заметки / аннотация. Проходит через санитайзер HTML / текст. |
| `url` | string | Да | Прямая ссылка на сообщение в Telegram (например, `"https://t.me/durov/123"`). |
| `metrics` | object | Да | Метрики сообщения: `{"views": int, "forwards": int}`. |

## 4. Идемпотентность и статус `empty`

1. **Идемпотентность:** ghsub ведёт учёт отправленных `edition_id` в `/var/lib/tldw/ghsub/unagi_sent_editions.json`. При повторном появлении файла с тем же `edition_id` письмо повторно **не отправляется**, а файл перемещается в `done/`. Записи старше 60 дней автоматически ротируются.
2. **Пустой выпуск (`items: []`):** Если за указанный период новых публикаций не было, unagi формирует валидный выпуск с `items: []`. ghsub фиксирует статус `empty`, **не отправляет письмо** адресату и перемещает файл в `done/`.
