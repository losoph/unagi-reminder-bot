# Контракт обмена unagi → ghsub: выпуск Telegram-каналов (JSON v1)

**Версия схемы:** `1.0`  
**Статус:** Согласован (18.10.2026)  
**Участники:** [unagi](https://github.com/losoph/unagi-reminder-bot) (источник выпусков) → [ghsub](https://github.com/losoph/ghsub) (почтовый отправитель)  
**Связанные документы:** [ADR-006](adr/ADR-006-email-aggregator-and-server-profile.md), [ADR-007](adr/ADR-007-recipients-and-unagi-intake.md)

---

## 1. Назначение и модель взаимодействия

unagi собирает публикации отслеживаемых Telegram-каналов, ранжирует их по расписаниям пользователей и формирует выпуски (дайджесты и подборки). Для доставки в почту unagi сериализует сформированный выпуск в формат **JSON v1** и передаёт его ghsub через локальный спул-каталог.

ghsub действует как надёжный почтовый приёмник (intake):
1. Валидирует структуру JSON v1 и схему;
2. Проверяет наличие адресата в локальной конфигурации (`recipients`);
3. Дедуплицирует выпуск по ключу идемпотентности `edition_id`;
4. Выполняет безопасный рендеринг письма (HTML + plain text alternative) с группировкой карточек по каналам и блоком «Коротко»;
5. Отправляет письмо через системный транспорт (msmtp / Brevo);
6. Фиксирует статус и раскладывает файлы по подкаталогам (`done/`, `rejected/`).

---

## 2. Транспорт и файловый обмен

- **Спул-каталог по умолчанию:** `/var/lib/tldw/ghsub/unagi-inbox/` (на сервере aiqu).
- **Атомарность записи:** unagi формирует выпуск во временном файле на той же файловой системе (например, `.tmp_edition_<edition_id>.json`) и атомарно переносит его в спул через `rename` / `os.replace` с именем `<edition_id>.json`.
- **Подкаталоги обработки:**
  - `unagi-inbox/done/` — выпуск успешно отправлен адресату, либо пропущен как дубликат, либо помечен как `empty` (пустой выпуск).
  - `unagi-inbox/rejected/` — файл повреждён, не соответствует схеме `1.0` или содержит неизвестного адресата (`recipient`). Причина отклонения пишется в журнал ghsub.
  - При ошибке почтового транспорта (сбой сети, временная ошибка SMTP) файл **остаётся во входящих** и повторяется при следующем запуске обработчика (каждые 5 минут).

## 3. Спецификация полей схемы JSON v1

### Корневой объект

| Поле | Тип | Обязательность | Описание и ограничения |
|---|---|---|---|
| `schema_version` | string | Да | Строго `"1.0"`. |
| `edition_id` | string | Да | Уникальный непустой идентификатор выпуска (ключ идемпотентности). Например, `"tg-digest-20261018-0700-primary"`. |
| `kind` | string | Да | Тип выпуска: `"digest"` (периодический дайджест), `"feed"` (лента/подборка) или `"raw_feed"` (сырые посты Ленты для ранжирования в ghsub, своя схема — см. [раздел 6](#6-выгрузка-ленты-kind-raw_feed)). |
| `recipient` | string | Да | Символический ключ адресата (например, `"primary"`). Должен присутствовать в секции `recipients` в `/etc/tldw/ghsub.yml`. |
| `title` | string | Да | Заголовок выпуска. Используется как основа темы письма и главного заголовка `<h1>`. |
| `period` | string | Да | Описание периода (например, `"weekly"`, `"daily"` или `"11–18 октября 2026"`). |
| `window` | object | Да | Временные границы выпуска (см. ниже). |
| `telegraph_url` | string \| null | Да | Ссылка на опубликованную версию в Telegraph (или `null`, если отсутствует). |
| `manage_url` | string | Нет | Опциональная ссылка на управление подпиской (например, диалог с ботом unagi). |
| `unsubscribe_url` | string | Нет | Опциональная ссылка на отписку. |
| `items` | array[object] | Да | Список публикаций (может быть пустым `[]`). |

### Объект `window`

| Поле | Тип | Описание |
|---|---|---|
| `from` | string | Дата/время начала окна в формате ISO 8601 (например, `"2026-10-11T00:00:00Z"`). |
| `to` | string | Дата/время конца окна в формате ISO 8601 (например, `"2026-10-18T00:00:00Z"`). |
| `timezone` | string | Имя часового пояса IANA (например, `"Europe/Moscow"`). |

### Элементы массива `items`

Каждый элемент представляет собой публикацию Telegram-канала:

| Поле | Тип | Обязательность | Описание и ограничения |
|---|---|---|---|
| `post_id` | int \| string | Да | Идентификатор сообщения в канале. |
| `published_at` | string | Да | Дата/время публикации в формате ISO 8601. |
| `channel` | object | Да | Объект канала: `{"username": string, "title": string}`. |
| `tier` | string | Да | Уровень отображения: `"card"` (полная карточка) или `"brief"` (краткая заметка в блоке «Коротко»). |
| `title` | string | Да | Заголовок новости / карточки. Экранируется санитайзером. |
| `summary` | string | Да | Текст заметки / аннотация. Проходит через санитайзер HTML / текст. |
| `url` | string | Да | Прямая ссылка на сообщение в Telegram (например, `"https://t.me/durov/123"`). |
| `metrics` | object | Да | Метрики сообщения: `{"views": int, "forwards": int}`. |

## 4. Идемпотентность и статус `empty`

1. **Идемпотентность:** ghsub ведёт учёт отправленных `edition_id` в `/var/lib/tldw/ghsub/unagi_sent_editions.json`. При повторном появлении файла с тем же `edition_id` письмо повторно **не отправляется**, а файл перемещается в `done/`. Записи старше 60 дней автоматически ротируются.
2. **Пустой выпуск (`items: []`):** Если за указанный период новых публикаций не было, unagi формирует валидный выпуск с `items: []`. ghsub фиксирует статус `empty`, **не отправляет письмо** адресату и перемещает файл в `done/`.

## 6. Выгрузка Ленты (`kind: "raw_feed"`)

**Статус:** добавлено 18.10.2026 по решениям владельца (ghsub: `docs/sprint/issues-logic-2026-10-18.md`).
Читатель формата в ghsub — трек GH8. Поля ниже согласованы; менять их только по согласованию.

### 6.1. Назначение и разделение ответственности

- Лента на почту — источник ghsub. unagi отдаёт **сырые посты** каналов Ленты пользователя с метриками
  и **не отбирает и не ранжирует** их.
- ghsub ранжирует по формуле `(views + 5·forwards + 2·reactions) / медиана views канала`, дедуплицирует
  по внешним URL и 4-граммам, берёт топ-15 и не больше 6 постов на канал, после чего вклеивает Ленту
  в общее недельное письмо (воскресенье 07:10 МСК, повторы 07:30 и 08:00).
- Telegram-сессией владеет только unagi: ghsub к Telegram не подключается, поэтому всё, что нужно для
  ранжирования и дедупликации (метрики, текст, внешние ссылки), едет в выпуске.

### 6.2. Кому и когда

- Выпуск пишется для каждого пользователя с подтверждённым адресом и включённой **почтовой доставкой Ленты**
  (бот: `/email` → «Лента за неделю: 📧 Почта»; в БД — токен `feed` в `user_emails.email_periods`).
  Лента в Telegram при этом работает как раньше.
- Раз в неделю: выгрузка стартует в **воскресенье 05:30 МСК** (проверка расписания раз в 5 минут) и должна
  лежать в ящике к **06:15 МСК**. Каждая ISO-неделя выгружается один раз (отметка в `app_meta`
  `ghsub_raw_feed_last_week`); при ошибке записи выгрузка повторяется на следующей проверке целиком.
- Если к **08:00 МСК** (последний повтор склейки) выгрузка так и не выполнилась (бот лежал), неделя
  пропускается: ghsub опоздавшую выгрузку Ленты всё равно не берёт.
- Выгрузка включена только при `EMAIL_DELIVERY=ghsub`.
- Перед выгрузкой unagi дочитывает каналы Ленты за окно и освежает метрики постов (один раз на канал для
  всех пользователей). Сбой чтения канала выгрузку не останавливает — берутся уже сохранённые посты.

### 6.3. Корневой объект

| Поле | Тип | Обязательность | Описание |
|---|---|---|---|
| `schema_version` | string | Да | Строго `"1.0"`. |
| `edition_id` | string | Да | `unagi:raw_feed:<recipient>:<ISO-неделя>`, например `unagi:raw_feed:unagi-42:2026-W42`. Неделя — ISO-неделя воскресенья выгрузки. Повторная запись той же недели даёт тот же `edition_id`. |
| `kind` | string | Да | Строго `"raw_feed"`. |
| `recipient` | string | Да | Ключ адресата `unagi-<user_id>`, как у выпусков `digest`. |
| `recipient_email` | string | Да | Подтверждённый адрес. Одна строка `a@b.c` без пробелов; если адрес не проходит проверку, выпуск не пишется вовсе. |
| `period` | string | Да | Строго `"weekly"`. |
| `generated_at` | string | Да | Момент сборки выпуска, ISO 8601 UTC (`...Z`). |
| `window` | object | Да | `{"from", "to", "timezone"}`: `to` — воскресенье 05:30 МСК (в UTC), `from` = `to` − 7 суток, `timezone` = `"Europe/Moscow"`. В выпуск попадают посты с `from < published_at ≤ to`. |
| `items` | array[object] | Да | Плоский список постов (может быть пустым `[]`). |

Полей `title`, `telegraph_url`, `manage_url` у `raw_feed` нет: письмо собирает ghsub.

### 6.4. Элементы `items`

| Поле | Тип | Описание |
|---|---|---|
| `post_id` | int | Номер сообщения в канале. |
| `published_at` | string | Время публикации, ISO 8601 UTC (`...Z`). |
| `channel` | object | `{"username": string, "title": string}`; `username` без `@`, `title` без разметки (если названия нет — равен `username`). |
| `url` | string | Строго `https://t.me/<username>/<post_id>`. |
| `text` | string | Текст поста без разметки (HTML снят, служебные строки «Переслано из…» и эмодзи-баннеры убраны, пробелы и переводы строк схлопнуты в один пробел), не длиннее 500 символов; длинный текст обрезается по слову с `…`. |
| `external_urls` | array[string] | Внешние ссылки поста: из текста и спрятанные под словами (text-link, превью ссылки). Только `http(s)`, без параметров `utm_*` (без учёта регистра), `fbclid`, `yclid`; без повторов, в порядке появления. Ссылки на `t.me` / `telegram.me` не считаются внешними и не выгружаются. |
| `metrics` | object | `{"views": int, "forwards": int, "reactions": int}` — целые ≥ 0; неизвестная метрика = 0. `reactions` — сумма всех реакций поста. |

Порядок `items` — по времени публикации (по возрастанию), затем по `username` и `post_id`. Порядок
не означает важности.

### 6.5. Что не выгружается и ограничения

- Репосты (пересланные сообщения): в Telegram у пересланного сообщения нет своего текста.
- Опросы.
- Медиа (фото, видео, документ, голосовое, альбом, стикер) с подписью короче 40 символов (длина считается по
  очищенному тексту). Превью ссылки медиа не считается. Для постов, сохранённых до появления признаков
  медиа/репоста (колонки `channel_posts.media_kind`, `is_forward`), медиа неизвестно и пост выгружается;
  репост в них распознаётся по `fwd_from_*`.
- Посты без текста.
- Не больше **400** постов и **1 МБ** (1 000 000 байт сериализованного JSON) на выпуск. Если постов больше,
  урезание идёт по очереди по каналам (от свежих к старым), чтобы один частый канал не вытеснил остальные;
  это не ранжирование, а только соблюдение лимита.

### 6.6. Транспорт

Как у остальных выпусков (раздел 2): тот же ящик (`EMAIL_OUTBOX_DIR`, по умолчанию `storage/ghsub-outbox`),
запись во временный `.tmp_edition_<edition_id>.json` в том же каталоге и атомарный `os.replace` в
`<edition_id>.json`.

## 7. Недельные дайджесты для почты

ghsub склеивает недельный выпуск в воскресенье 07:10 МСК и берёт файлы, лежащие в ящике к 06:15.
Поэтому при `EMAIL_DELIVERY=ghsub` еженедельный дайджест пользователя, у которого он переключён на почту,
готовится в **воскресенье 05:00 МСК** независимо от выбранных в боте дня и времени (выбор сохраняется и
вернётся, если переключить дайджест обратно в Telegram). Запас нужен на интервал цикла дайджестов
(`DIGEST_CHECK_INTERVAL_SECONDS`, по умолчанию 30 минут) и чтение каналов. Ежедневные дайджесты того же
воскресенья, назначенные позже, по существующему правилу выпуска дня уходят вместе с недельным.
