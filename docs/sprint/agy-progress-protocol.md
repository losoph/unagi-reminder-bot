# Протокол отчётности исполнителя

Наблюдение за работой исполнителя разделено на три слоя **без пересечений**.
Каждый слой отвечает строго за своё, и ни один не повторяет данные другого.

| Слой | Источник | Отвечает на вопрос | Чего в нём быть НЕ должно |
|---|---|---|---|
| 1. Факты | `git log`, `git show` | **Что** изменилось: файлы, диффы, добавленные тесты | пересказ диффа словами |
| 2. Ход работы | `scripts/agy_watch.sh reasoning` (stream-json) | **Как** исполнитель шёл к решению: шаги, рассуждения | итоговые решения (они в слое 3) |
| 3. Журнал решений | `docs/sprint/progress.md` (пишет исполнитель) | **Почему** так, и чем пришлось заплатить | список файлов, счётчики тестов, дифф |

## Требование к исполнителю (слой 3)

После каждой задачи допиши в `docs/sprint/progress.md` блок ровно такого вида,
**3-5 строк, только суждения** — файлы и тесты уже видны в git, не дублируй их:

```
## T<N> <название> — <commit sha>
- Решение: <что выбрал из нескольких вариантов и почему именно так>
- Компромисс: <чем заплатил, что осталось неидеальным>
- Отступление: <если отошёл от плана — что и почему; иначе строку не писать>
- Для следующей очереди: <что обнаружил по ходу и что это значит для T8-T13; иначе не писать>
```

Правила:
- Пиши в том же коммите, что и саму задачу.
- Не пиши сюда «изменил файл X», «добавил N тестов», «ruff ok» — это слой 1 и проверка наблюдателя.
- Если решение было безальтернативным и компромиссов нет — блок всё равно нужен, но короткий.
