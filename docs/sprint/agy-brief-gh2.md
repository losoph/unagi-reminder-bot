# GH2 — почтовые выпуски unagi через ghsub (сторона unagi, за флагом)

Решение 18.10: unagi = Telegram, ghsub = почта. Приёмник в ghsub уже есть (контракт — docs/sprint/ghsub-contract-json-v1.md, копия из репозитория ghsub; прочитай целиком). Сейчас unagi сам отправляет email-дайджесты (email_digest.py, формат TG1).

Сделай:
1. Переменная окружения EMAIL_DELIVERY (через config.py, по умолчанию "unagi" — поведение не меняется). При "ghsub" — в том месте, где сейчас отправляется письмо email-дайджеста, вместо отправки собрать выпуск JSON v1 из тех же данных (те же посты, что ушли бы в письмо; tier card/brief — как в формате TG1: до 3 карточек на канал, остальное brief) и атомарно записать файл в каталог EMAIL_OUTBOX_DIR (по умолчанию storage/ghsub-outbox; .tmp → os.replace). Курсоры/отметки отправки двигать так же, как после успешной отправки письма (unagi хранит курсор, ghsub — stateless).
2. edition_id детерминированный: unagi:digest:<recipient>:<period>:<scheduled_at_iso> (повтор той же отправки даёт тот же edition_id — ghsub отбросит дубль). recipient = "unagi-<user_id>" (внешний ключ; адрес почты в файл НЕ писать — его знает конфиг ghsub). manage_url = https://t.me/<BOT_USERNAME>?start=email (если имя бота неизвестно — поле не писать).
3. Проверка файлов: все ссылки только http(s); тексты — после очистки TX1 (post_text), без HTML.
4. Тесты tests/test_gh2_outbox.py: флаг по умолчанию — письмо уходит прежним путём, файла нет; EMAIL_DELIVERY=ghsub — письма нет, файл есть, JSON валиден по контракту (проверь обязательные поля и типы), повтор → тот же edition_id; запись атомарна (нет .tmp после успеха).
5. Чек-лист включения для владельца — docs/sprint/ghsub-switch-checklist.md: (а) /etc/tldw/ghsub.yml: recipients unagi-<id> → email (id — из БД, команда sqlite3 только на чтение для списка user_id с подтверждённой почтой, без вывода адресов в общий лог); unagi_intake.inbox_dir = /root/projects/unagi-reminder-bot/storage/ghsub-outbox; (б) cron приёмника ghsub (*/5); (в) EMAIL_DELIVERY=ghsub в .env unagi + пересоздание контейнера с GIT_SHA; (г) проверка первого выпуска и откат (EMAIL_DELIVERY=unagi).
