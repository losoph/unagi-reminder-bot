# Argon о модели рассылок (18.10.2026, веб-Gemini «Высокая»)

Два захода: (1) аудит решений владельца на сложность и соответствие практике UI/UX; (2) подтверждение новой логики владельца. Итог — «подтверждаю с правками». Решения владельца — docs/sprint/owner-decisions-2026-10-17.md.

## 1. Аудит решений (кратко)
- «Папка → три периода (день/неделя/месяц) → слоты» — фрактальная модель; зрелые продукты (Mailbrew, Readwise Daily Digest) используют плоскую «Рассылку»: источники + одно правило отправки. Папки Telegram/Feedly/Inoreader вообще не имеют времени доставки.
- Одно слово «тег» в трёх смыслах (фильтр закладок/напоминаний, папка-рассылка дайджеста, маркер Ленты): в интерфейсе дайджеста говорить «папка», «тег» — только закладкам/напоминаниям.
- Раздельные списки каналов Ленты и дайджеста — канал добавляется дважды; автодоставка Ленты стирает разницу с дайджестом (решать 24.10 вместе с официальной лентой Telegram).
- Обязательная анкета при создании папки — трение; цель «папка = рассылка» достигается дефолтом и явной подписью.
- Email на старом пути period при новой схеме курсоров = два планировщика и два курсора на подписку; мигрировать email в общую схему с delivery=email.
- MAX — вне активной дорожной карты до фактов недоставки (за 30 дней 0 из 16).

## 2. Подтверждение новой логики — правки
1. **Курсор снова один на подписку** (1 канал = 1 папка = 1 расписание): таблица курсоров на пару (расписание, подписка) не нужна.
2. **Разные периоды внутри одной папки** (в т.ч. tag = NULL): dry-run проверяет однородность period в каждой папке; неоднородные группы — конфликт (решает владелец до миграции) или отдельная папка «<имя> — неделя».
3. **Перенос канала между папками / смена периода папки:** курсор подрезается окном нового периода (не старше now − новый период), next_send_at пересчитывается — иначе посты за месяц уйдут в дневной выпуск.
4. **Мастер новой папки:** имя/период/время — в FSM; папка и подписка создаются одной транзакцией после выбора времени; никаких «мёртвых» папок без расписания.
5. **«Основной» дайджест** — системная папка (нельзя удалить); пустой — скрыт, next_send_at = NULL. Удаление папки с каналами — выбор [Перенести в Основной] / [Отписаться от каналов], с подрезкой курсора.
6. **Канал раньше был и в daily, и в weekly:** остаётся в daily; недельный обзор — подсказка со ссылкой на Ленту за неделю.
7. **Шаг «доставка»** скрыт, пока вариант один (Telegram). **Слоты** (08:00 + 19:00, один курсор) — только у ежедневной папки и только в настройках, мастер спрашивает одно время.
8. **Почта без ворот G3:** email-подписки (2 пользователя) мигрируют в обычные папки с delivery = 'email' (без шага в интерфейсе); новый планировщик для delivery=email вызывает текущий email_digest (формат TG1); когда ghsub готов — замена вызова на запись JSON v1, старый почтовый код удаляется. Второго планировщика нет, T20 не ждёт ghsub.
9. **Конфликты:** строгая миграция, без UI конфликтов; владелец правит 1–2 случая руками до миграции.

## 3. Контракт JSON v1 unagi → ghsub (почта)
- Расписание и курсор хранит только unagi: планировщик собирает выпуск, атомарно пишет JSON в спул-каталог (.tmp → rename) и двигает курсор.
- ghsub — stateless-отправщик (`ghsub --once`), не знает о курсорах Telegram.
- Идемпотентность: ghsub дедуплицирует по `edition_id` = `unagi:digest:<recipient>:<folder_id>:<scheduled_at_iso>`.
- Корневые поля: `schema_version` ("1.0"), `edition_id`, `kind` ("digest"|"feed"), `recipient` (внешний ключ адресата, не user_id), `title` (имя папки), `period` (day|week|month), `window` {from, to, timezone}, `telegraph_url`.
- `items[]` (уже очищены TX1): `post_id`, `published_at`, `channel` {username, title}, `tier` ("card"|"brief"), `title`, `summary`, `url`, `metrics` {views, forwards}.
- Управление в письме: `manage_url` / `unsubscribe_url` — deep-link `https://t.me/<bot>?start=folder_<id>`.
