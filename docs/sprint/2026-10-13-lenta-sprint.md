## Что строим

**Лента** — ранжированная подборка до 50 постов из каналов, которые пользователь добавил в Ленту
вручную (пересылкой поста, ссылкой или из списка своих подписок — T24b). У подписки Ленты **нет
периодичности**: все каналы Ленты обсчитываются одним алгоритмом за выбранный период — **день,
неделя, месяц** — по запросу пользователя (автодоставка — только если пользователь сам включил её
кнопкой под выпуском, T24c). Сверху — посты с наибольшим **охватом и пересылками**. Выпуск —
**только страница Telegraph**; в чат приходит короткое сообщение со ссылкой. У каждой подписки может
быть **тег** — тематический раздел: страница Telegraph одна, посты на ней разбиты по разделам
тегов (наверху — каналы без тега, ниже — теги по алфавиту, T23).

## 1. Решения владельца (не обсуждаются)

1. Лента — **только Telegram-каналы**; выход — **только Telegraph** (+ короткое сообщение в чат).
2. **Лента на почту в unagi не делается.** Почта — зона ghsub; передача выпуска Ленты в ghsub —
   по контракту из `ghsub-candidates.md` §2.2, **вне этого спринта**.
3. Подписка Ленты **без периодичности**; период выбирается при запросе: день / неделя / месяц.
   Окно скользящее от момента запроса («день» = последние 24 ч). Автодоставка — **только opt-in**
   кнопкой в сообщении со ссылкой на выпуск (T24c), по умолчанию выключена.
4. До **50 постов**; главные сигналы — **охват (просмотры) и пересылки**.
5. **Тег** у подписки — тематический раздел. Лента одна, страница Telegraph одна, посты на ней
   сгруппированы по разделам: **наверху — посты каналов без тега, ниже — разделы тегов в
   алфавитном порядке**. На **вес** и отбор поста тег не влияет. Тег виден на публичной странице
   Telegraph — форма ввода тега об этом предупреждает.
6. Канал может быть **одновременно** в дайджесте и в Ленте — это независимые подписки.
7. **Курсор сканирования канала Лента двигает только «без дыр»**: если загрузка Ленты начиналась
   позже текущего курсора канала (`marker > last_scanned_at`), курсор не трогать. Иначе дайджест
   потеряет посты (факт 0.4). Это инвариант, на него обязателен тест.
8. Новый код — в отдельных модулях (`feed.py`, `feed_ranking.py`, `feed_render.py`), `main.py` —
   только регистрация роутера, кнопки «📰 В Ленту», строки в справке и запуск фоновой задачи
   автодоставки (T24c) рядом с другими `asyncio.create_task(...)`.
9. **Реклама не скрывается**: пост с рекламной маркировкой попадает в Ленту, если набрал высокий
   охват и пересылки (порог — 2.5), и получает значок `📢 Реклама`.
10. **Канал, добавленный в Ленту, сразу подтягивается в фоне** за 30 суток (T21), чтобы первая
    сборка «за месяц» не упиралась в таймаут.
11. **Подбор из личных подписок** (T24b) — только для владельца MTProto-сессии: список его
    диалогов никогда не показывается другому пользователю бота.

## 2. Алгоритм ранжирования (реализуется в T22 как чистые функции)

### 2.1 Окно и кандидаты

- Окно скользящее, конец — момент запроса `now`: **день** = 24 ч, **неделя** = 7×24 ч,
  **месяц** = 30×24 ч.
- Кандидаты — посты из `channel_posts` каналов активных (не на паузе) подписок Ленты пользователя,
  `window_start < post_time ≤ now`, с текстом.
- **Пометка рекламы** до ранжирования (`is_ad`, посты **не** удаляются): регэксп без учёта
  регистра по тексту — `\berid\b`, `^\s*реклама\b`, `#реклама`, `#ad\b`, `партн[её]рский материал`,
  `на правах рекламы`. Реклама участвует в перцентилях наравне со всеми; допуск — в 2.5.

### 2.2 Сигналы поста `p` канала `c`

```
age_h      = max(0.1, (now − p.time) в часах)
maturity   = max(0.25, 1 − exp(−age_h / 8))           # как в ranking.score_post
views_m    = p.views / maturity                        # охват с поправкой на «зрелость»

reach_abs  = log10(1 + views_m)                                        # охват
fwd_abs    = log10(1 + p.forwards)                                     # пересылки
reach_rel  = views_m / median_views[c]                 (None, если медианы нет)
fwd_rel    = (p.forwards / p.views) / median_fwd_rate[c]  (None, если нет)
engagement = (p.reactions_total + 2·p.replies) / p.views  (None, если нет просмотров или обоих полей)
fresh      = exp(−age_h / half_life),  half_life: день 12 ч, неделя 72 ч, месяц 240 ч
```

Медианы — `ranking.get_channel_medians(c)` (30 суток, ≥3 замера).

### 2.3 Нормировка и итоговый score

Каждый из пяти сигналов вовлечения переводится в **перцентиль внутри набора кандидатов этого
выпуска**: ранговый, ничьи — средний ранг, `P = (rank − 1) / (n − 1)`, при `n = 1` → `1.0`.
Отсутствующий сигнал (`None`) у поста **не участвует**: веса нормируются по имеющимся.

| Сигнал | Вес (env) | По умолчанию |
|---|---|---|
| `reach_abs` | `FEED_W_REACH` | 0.30 |
| `fwd_abs` | `FEED_W_FWD` | 0.25 |
| `reach_rel` | `FEED_W_REACH_REL` | 0.15 |
| `fwd_rel` | `FEED_W_FWD_REL` | 0.15 |
| `engagement` | `FEED_W_ENGAGEMENT` | 0.10 |

```
quality = Σ w_i · P_i / Σ w_i        (по имеющимся сигналам; нет ни одного → 0)
score   = 0.95 · quality + 0.05 · fresh
```

### 2.4 Один сюжет — одна карточка

Кластеризация кандидатов (дёшево, без эмбеддингов):

1. одинаковый первоисточник пересылки (`fwd_from_channel + fwd_from_post_id`, колонки — T21);
2. одинаковая первая внешняя ссылка в тексте после канонизации (нижний регистр хоста, без
   `utm_*`, `#фрагмента` и `/` в конце; ссылки на `t.me` не считаются);
3. похожий текст: нормализация (нижний регистр, без ссылок, эмодзи и пунктуации, первые 400
   символов), `difflib.SequenceMatcher(...).ratio() ≥ 0.6` для пар с разницей во времени ≤ 36 ч.
   Сравнивать только **топ-300** кандидатов по `score` (`quick_ratio()` как префильтр).

Кластер: представитель — пост с максимальным `score` (если один из постов — первоисточник
пересылки других, представитель — он). Score кластера:
`score_max + min(0.15, 0.05 · log2(число уникальных каналов))`. Остальные посты кластера идут
строкой «также в: …» (ссылки на их посты).

### 2.5 Разнообразие и лимит

Жадный отбор по убыванию: эффективный score = `score · 0.85^k`, где `k` — сколько постов этого
канала уже отобрано. Жёсткий потолок на канал `FEED_MAX_PER_CHANNEL_{DAY,WEEK,MONTH}` = 5 / 10 / 20.
Всего — `FEED_MAX_POSTS = 50`.

**Допуск рекламы:** `ad_strength` = среднее имеющихся перцентилей `reach_abs` и `fwd_abs` поста;
рекламный пост (`is_ad`) допускается к отбору, только если `ad_strength ≥ FEED_AD_MIN_PERCENTILE`
(0.75, верхняя четверть по охвату и пересылкам). Для кластера решает представитель.

### 2.6 Значки на карточке

- `🔥 ×N к норме` — если `reach_rel ≥ 2` (N округлить до целого);
- `↗️ ×N пересылок к норме` — если `fwd_rel ≥ 2`;
- `🆕` — пост моложе 24 ч в выпусках «неделя» и «месяц»;
- `📢 Реклама` — у допущенного рекламного поста (`is_ad`).

### 2.7 Свойства, которые обязаны проверять тесты T22

- больше просмотров при прочих равных → score не ниже; то же для пересылок;
- `fwd_abs` + `fwd_rel` весят больше `engagement`: пост с ×10 пересылок обгоняет пост с ×10 реакций;
- одинаковые посты разного возраста — выше более свежий (свежесть только развязывает);
- реклама с `erid` и слабыми охватом/пересылками в выпуск не попадает; реклама из верхней
  четверти по охвату и пересылкам попадает со значком `📢 Реклама`;
- потолок на канал (5 / 10 / 20) и общий лимит 50 соблюдаются; при 3 каналах и 60 постах за день —
  не больше 5 с канала;
- три канала об одном сюжете → одна карточка, `also_in` из двух каналов, бонус применён;
- посты без реакций/ответов/медиан не падают и ранжируются по имеющимся сигналам;
- результат детерминирован (сортировка с явным тай-брейком по `post_time`, затем `channel`, `post_id`).

### T21. Загрузка постов окна и свежие метрики
- `feed.ingest_window(channels, window_start)`: для каждого канала `fetch(username, marker)`, где
  `marker = max(window_start, курсор канала)` если курсор есть, иначе `window_start`;
  `upsert_channel_posts`. **Курсор канала** — только по правилу 1.7 (тест обязателен: дайджест
  после загрузки Ленты получает все свои посты).
- `channel_source.refresh_metrics(username, post_ids) -> int`: MTProto
  `messages.GetMessagesViewsRequest(peer, id=batch, increment=False)` батчами по 100; обновляет
  `views, forwards, replies, metrics_at` новой функцией `update_post_metrics(...)` (реакции не трогать).
  Обновлять только посты окна, у которых `metrics_at` старше порога: день 30 мин, неделя 3 ч,
  месяц 12 ч. `FloodWaitError` и прочие ошибки — прекратить обновление этого канала, работать
  на старых метриках, `WARNING` в лог. Без MTProto (web) — обновление пропускается.
- Колонки `channel_posts.fwd_from_channel TEXT, fwd_from_post_id INTEGER`: заполнять в
  `_fetch_mtproto` из `message.fwd_from` (канал-первоисточник и `channel_post`), если доступно.
- Конкурентность: общий семафор с дайджестом (`DIGEST_FETCH_CONCURRENCY`), на пользователя — один
  сбор одновременно.
- **Фоновая подгрузка при добавлении** (решение 1.10): после успешного добавления канала в Ленту
  (все пути T20: из FSM, из карточки дайджеста; позже T24b) — `asyncio.create_task` с
  `ingest_window([канал], now − 30 суток)` под тем же семафором. Повторное добавление того же канала
  во время подгрузки — без второй задачи. Ошибка — `WARNING` в лог, пользователь не тревожится.
  Правило курсора 1.7 действует и здесь.
- Тесты: фейковый клиент (как `tests/test_digest_pipeline.py:353`) — батчи по 100, порог свежести,
  FloodWait, web без refresh, правило курсора, `fwd_from`, фоновая подгрузка при добавлении (одна
  задача на канал, окно 30 суток).
**Готово:** перед ранжированием у постов окна свежие просмотры и пересылки, дайджест не теряет посты.

### T22. Ранжирование `feed_ranking.py`
- Чистые функции без I/O (вход — посты и медианы, `now` и `period` явно): `mark_ads`,
  `percentiles`, `score_candidates`, `cluster_candidates`, `select_diverse` (с допуском рекламы
  по 2.5), итоговая `rank_feed(posts, medians_by_channel, period, now) -> list[FeedItem]`.
- `FeedItem`: `rank, score, post, also_in: list[post], badges: list[str], channel_title, tag, is_ad`.
- Параметры и веса — из env по разделу 2 (значения по умолчанию в коде).
- Тесты: все свойства 2.7 + синтетический набор на 3 канала (крупный / средний / маленький)
  с ожидаемым **топ-3** и проверкой, что крупный канал не занимает всю Ленту.
**Готово:** детерминированный топ-50 по разделу 2, покрытый тестами свойств.

### T23. Страница Telegraph `feed_render.py`
- `telegraph_publisher.publish_page(title, nodes)` — общий метод публикации (вынести из
  `publish_digest` без изменения его поведения: токен, повтор при `ACCESS_TOKEN_INVALID`, усечение).
- Заголовок: «Лента за день · 12.10» / «за неделю · 06.10–12.10» / «за месяц · 13.09–12.10» (≤256).
- Верх: «50 постов из 23 каналов · отбор по охвату и пересылкам · окно …», `hr`.
- **Разделы по тегам** (решение 1.5): `rank_feed` отбирает топ-50 по всей Ленте как обычно, затем
  отобранные посты группируются по тегу подписки. Порядок разделов: сначала посты каналов **без
  тега** (заголовок `h3` «Без тега», если на странице есть и другие разделы), затем разделы тегов
  по алфавиту (`str.casefold`), заголовок `h3` «#тег · N». Внутри раздела — по score. Нумерация
  сквозная в порядке вывода. Раздел без постов не выводится. Нет ни одного тега — без заголовков
  разделов, просто список.
- Карточка: `h4` «1. Канал» (тег — в заголовке раздела, на карточке не повторяется); `p` метрик «👁 120K · ↗️ 340 · ❤️ 1,2K · 💬 50 · 🔥 ×3 к норме ·
  12.10 09:14» (компактные числа: 999, 1,2K, 12K, 1,2M); `p` — первое предложение жирным + текст
  до `FEED_POST_CHARS` (600); `p` — «Читать» и «также в: Канал B, Канал C» (ссылки на их посты).
- Если хоть один канал читался через web — строка «ℹ️ Метрики части каналов неполные».
- Никаких user_id, настроек и тегов-приватностей сверх отображения (страница публичная).
- Тесты: узлы карточки, компактные числа, `also_in`, значки, размер 50 длинных постов → усечение с плашкой.
**Готово:** Лента читается одной страницей Telegraph, у каждого поста видны охват, пересылки и тег.

### T24. Сборка по запросу и кеш
- Кнопки периода → правка сообщения на «⏳ Собираю Ленту за неделю…» → `ingest_window` →
  `refresh_metrics` → `get_feed_candidate_posts` → `rank_feed` → `feed_render` → `publish_page` →
  сообщение: «📰 Лента за неделю · 50 постов из 23 каналов» + «📖 Открыть» (превью ссылки включено)
  + кнопки [☀️ День] [🗓 Неделя] [📆 Месяц].
- Кеш: тот же период и тот же `subs_hash` (набор каналов + теги + паузы) моложе `FEED_CACHE_MINUTES`
  (15) → отдать сохранённую ссылку без пересборки.
- Ограничения: один сбор на пользователя одновременно; повтор раньше `FEED_MIN_INTERVAL_SECONDS`
  (60) без кеша → «Подожди минуту»; общий таймаут сборки `FEED_BUILD_TIMEOUT_SECONDS` (120) → вежливая
  ошибка, частичная Лента не публикуется.
- Пусто: нет каналов → подсказка, как добавить; нет постов за окно → «За неделю в каналах Ленты
  постов не было».
- Лог одной строкой `feed_build user=… period=… channels=… candidates=… clusters=… items=…
  refreshed=… cache=hit|miss duration_ms=…`.
- Тесты: оркестрация с моками (кеш hit/miss, лимит частоты, таймаут, пусто, нет каналов),
  смена тега канала сбрасывает кеш (`subs_hash`).
**Готово:** /feed → период → через несколько секунд ссылка на актуальную картину дня/недели/месяца.

### T24b. Подбор каналов из личных подписок (решение 1.11)
- При **первом** открытии `/feed` (флаг в БД, например `feed_user_state(user_id PK,
  onboarding_shown_at)`) пользователю предлагается добавить каналы вручную, по одному, из его личных
  подписок. Позже тот же список открывается кнопкой «➕ Из моих подписок» на экране `/feed`.
- **Только владелец MTProto-сессии**: `channel_source` запоминает `account_id` из `get_me()` при
  старте; предложение и кнопка есть, только если `user_id == account_id`. Остальным — обычная
  подсказка «Как добавить». Без MTProto — тоже подсказка.
- `channel_source.list_personal_channels(limit=20) -> list[dict]`: `iter_dialogs(limit=300)`
  (порядок Telegram — по последней активности); оставить **вещательные каналы** (`broadcast`,
  не группы) с публичным `username`, последнее сообщение не старше 30 суток, не входящие уже в
  Ленту пользователя; сортировка — `unread_count` по убыванию, при равенстве — более свежая
  активность; первые 20. Поля: `username, title, unread_count`. `FloodWaitError`/ошибка → пустой
  список и `WARNING`.
- Экран: «Выбери каналы для Ленты — по одному. Это твои активные подписки с наибольшим числом
  непрочитанных:» + по кнопке на канал «➕ Название · 123» (по индексу, `callback_data` ≤ 64 байт;
  список кешируется на пользователя на 15 мин) → добавление тем же путём, что T20 (с фоновой
  подгрузкой T21), кнопка меняется на «✅ Название»; внизу [✅ Готово] [🔙 К Ленте].
- Список диалогов **не логировать** и не сохранять в БД дольше кеша.
- Тесты: фейковый `iter_dialogs` (каналы, группы, без username, старые, уже в Ленте, сортировка по
  непрочитанным, лимит 20), чужой `user_id` не видит кнопку и не вызывает `iter_dialogs`, флаг
  первого показа, добавление по индексу, FloodWait.
**Готово:** владелец при первом открытии Ленты в несколько тапов набирает её из своих подписок.

### T24c. Автодоставка по выбору (решение 1.3)
- Под сообщением со ссылкой на выпуск — кнопка «🔔 Присылать автоматически» (или «🔕 Не присылать»,
  если для этого периода уже включено). Нажатие → подтверждение: «Лента за неделю
  будет приходить {format_digest_schedule(...)} — в то же время, что дайджест этого периода
  (меняется в настройках дайджеста)» + [✅ Включить] [Отмена]. Соответствие периодов: день → daily,
  неделя → weekly, месяц → monthly; настройки — `get_digest_settings` с теми же значениями по
  умолчанию, что у дайджеста.
- Таблица `feed_autodelivery(id PK, user_id, period, last_run_at, created_at, UNIQUE(user_id,
  period))` — не больше трёх строк на пользователя (по одной на период). `next_run_at` не храним: срок = `get_next_digest_time(period, last_run_at или
  created_at, settings)` — так смена времени дайджеста подхватывается сама. Функции расчёта
  получать через `configure(...)` (паттерн T14b), не импортируя `main`.
- Фоновая задача `feed.run_autodelivery_loop()` (проверка раз в `FEED_AUTODELIVERY_CHECK_SECONDS`,
  120), запуск в `main` рядом с другими `create_task`. Срок наступил → сборка тем же конвейером T24
  (кеш разрешён, ограничение частоты не действует), сообщение как в T24 с пометкой «🔔 автодоставка»;
  `last_run_at = now`. Нет активных каналов или постов → без сообщения, срок сдвигается. Ошибка
  сборки → `WARNING`, повтор в следующем цикле, после 3 неудач — пропуск до следующего срока
  (одно сообщение на срок, не больше).
- Экран `/feed`: строка «🔔 Автодоставка: неделя — в воскресенье в 18:00» для включённых; отключение —
  той же кнопкой под выпуском или кнопкой на экране `/feed`.
- Справка (`bot_help`): строка про автодоставку.
- Тесты: расчёт срока с явным `now`, смена настроек дайджеста, один выпуск на срок, повтор и
  пропуск после 3 ошибок, отключение.
**Готово:** пользователь одной кнопкой под выпуском получает Ленту по расписанию, по умолчанию
автодоставки нет.

## 6. Правила исполнения

- Каждая задача — отдельный коммит `feat: … (T19)` со своими тестами и блоком в `progress.md`
  в том же коммите.
- Перед коммитом зелёные `ruff check .` и `python -m unittest discover -s tests`.
- **Push запрещён** — пушит наблюдатель после ревью opencode.
- Секреты (`.env`, `TELEGRAM_USER_SESSION`, msmtprc) не читать и не переносить в репозиторий.
  Сеть и прод не трогать: MTProto в тестах — только фейковый клиент.
