Задача LV2 — переработать вывод Ленты в Telegraph так, чтобы он читался как удобная лента новостей, а не как список служебных карточек.
Ветка feat/feed-render-v2, этот worktree. git push запрещён — только локальный коммит. Никаких pip install; тесты и линтер — только
~/.venvs/unagi/bin/python и ~/.venvs/unagi/bin/ruff; не запускай команды, ждущие stdin; файлы пиши инструментом. Секреты, сеть и прод не трогай.

Менять можно ТОЛЬКО feed_render.py (чистые функции без I/O), tests/test_feed_render.py и тесты, которые проверяют текст страницы
(tests/test_feed_t24*.py, tests/test_feed_autodelivery.py — только если ломаются), блок «LV2» в docs/sprint/progress.md и описание страницы в docs/architecture.md.
Сигнатуры `render_feed(...)`, `build_feed_title(...)` и поля `FeedItem` (feed_ranking.py: rank, score, post, also_in, badges, channel_title, tag, is_ad) НЕ менять.
Разрешённые теги Telegraph: a, aside, b, blockquote, br, code, em, figcaption, figure, h3, h4, hr, i, iframe, img, li, ol, p, pre, s, strong, u, ul, video.

ПРОБЛЕМЫ ТЕКУЩЕЙ СТРАНИЦЫ (реальный выпуск владельца, 7 каналов): заголовок каждой карточки — название канала (пять одинаковых «Не баг, а фича»),
строка метрик «👁 10K · ↗️ 563 · ❤️ 40 · ↗️ ×6 пересылок к норме · 15.10 08:10» перегружена и непонятна, первая фраза поста выделена жирным внутри абзаца
и склеена с остатком, нет «главного» наверху, нет ощущения ленты.

ТРЕБУЕМЫЙ ВИД (сверху вниз):
1. Вводная строка одним абзацем: «30 постов · 7 каналов · 16 окт» (для недели/месяца — диапазон «9–16 окт»), курсивом; ниже — `hr`.
2. Блок «Главное» (h3) — нумерованный список `ol` из 5 первых по рангу постов: в каждом `li` — заголовок поста жирным со ссылкой на пост, затем « — Канал · 👁 10K».
   Если постов меньше 5 — столько, сколько есть; если меньше 3 — блока нет.
3. Затем лента карточек в порядке ранга (разделы-теги сохраняются как раньше: сначала без тега, потом теги по алфавиту; нумерация сквозная НЕ нужна).
   Карточка:
   - `h4` — ЗАГОЛОВОК ПОСТА: первая осмысленная фраза до 90 символов (по предложению; если предложения нет или оно длиннее — по слову, с «…»); эмодзи в начале сохранять.
   - `p` с `i`: «Канал · 15 окт, 08:10» (название канала, время в поясе пользователя; для «сегодня/вчера» — «сегодня, 08:10» / «вчера, 19:19»).
   - `blockquote` — выдержка: остаток текста после заголовка, до 320 символов, обрезка по слову с «…», переносы строк схлопнуть в пробелы; если остатка нет — блока нет.
   - `p` — метрики и значки: «👁 10K · ↗ 563 · ❤ 40 · 💬 12» (показывать только имеющиеся), затем значки по-человечески: «🔥 в 6 раз больше пересылок, чем обычно» вместо «↗️ ×6 пересылок к норме»;
     существующие значки badges (🔥, 🆕, 📢 Реклама, ↗️ ×N …) сохранить смысл, но переписать понятным текстом (см. feed_ranking.py: как они формируются); затем ссылка «Читать в канале →»
     и, если есть, « · также в: Канал2, Канал3».
   - между карточками `hr`.
4. Подвал: `p` «Каналы в выпуске: bponline (12), truestorymedia (8), …» (по числу постов в выпуске, по убыванию), затем существующие плашки о неполных каналах/веб-метриках (ℹ️ …) как есть.
Текст поста НЕ экранировать вручную (Telegraph-узлы — текстовые), переносы строк в h4/blockquote не допускаются. Все эмодзи/русский текст допустимы.

ТЕСТЫ (tests/test_feed_render.py и др.; даты — от переданного `now`, никаких абсолютных дат против реального «сейчас»): вид карточки (h4 = заголовок поста, а не канал), обрезка по слову,
заголовок без точки, блок «Главное» (≥3 и <3 постов), «сегодня/вчера», значки по-человечески, подвал со счётчиками, разделы тегов, пустые метрики, очень длинные слова/ссылки в тексте,
размер итоговой страницы для 50 постов < 60 КБ в JSON. Покажи в итоге пример получившегося JSON-узла одной карточки.
