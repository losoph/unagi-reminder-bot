ТРЕБОВАНИЯ ВЛАДЕЛЬЦА (roadmap §4 п.1): админская операция; консистентный snapshot (backup API, не cp живой БД в WAL), СРАЗУ шифруется публичным recovery-ключом (age: `age -r <публичный ключ>`), наружу отдаётся только непрозрачный файл с checksum и версией формата; приватный ключ хранится вне сервера; на новом сервере — offline-restore с проверкой checksum, версии схемы и ОБЯЗАТЕЛЬНЫМ backup текущей БД; plaintext snapshot во временных каталогах НЕ оставлять, шифровать потоково; журналировать только факт, размер и хеш. Граница гарантии (в README): root исходного сервера может прочитать живую БД; схема защищает экспортируемый файл.

ЧТО СДЕЛАТЬ.
1. ops/aiqu/export_db.py с подкомандами:
   `export --db storage/bot_data.db --recipient <age1…> [--recipients-file F] --out storage/exports/ [--tag migrate]` — снимок через `sqlite3.Connection.backup` в ПАМЯТЬ (`:memory:`), затем `conn.serialize()` и подача байтов в stdin `age` (шифрование потоком, без plaintext на диске); результат — `bot_data-<время>-<tag>.db.age` (права 0600, запись атомарная через .partial) и манифест `…db.age.json`: `format_version`, `created_at` (UTC ISO), `sha256` ШИФРОТЕКСТА, `size`, `plaintext_size`, `sqlite_user_version`, `tables` (число), `app_schema` (значение из app_meta или user_version — выясни по data/database.py, что используется для версии схемы), `age_recipients_count`. Печать итога — одна строка `export ok path=… size=… sha256=…`, без содержимого БД.
   `verify --in FILE.age` — проверка sha256 по манифесту и формата; без ключа, ничего не расшифровывает.
   `restore --in FILE.age --identity KEYFILE --db storage/bot_data.db [--backup-dir storage/backups] [--dry-run] [--force-schema]` — (1) verify; (2) расшифровка потоком в память, `deserialize`/запись во временный файл в ЦЕЛЕВОМ каталоге с правами 0600 и немедленное `PRAGMA quick_check`; (3) сравнение версии схемы: если схема экспорта НОВЕЕ схемы кода/целевой БД — отказ (код 3), если старее — предупреждение; `--force-schema` разрешает; (4) если целевая БД существует — ОБЯЗАТЕЛЬНЫЙ снимок через ops/aiqu/backup_db.py (импортируй `snapshot` из него, не копируй код), без снимка восстановление не выполняется (код 4); (5) атомарная замена `os.replace`, удаление временного файла в любом исходе; `--dry-run` делает шаги 1–3 и ничего не заменяет. Контейнер на момент restore должен быть остановлен — выведи напоминание и проверь, что рядом нет живого WAL (`-wal` непустой → отказ с объяснением, `--force-wal` не нужен).
   Коды выхода: 0 успех; 1 ошибка ввода-вывода/age; 2 неверные аргументы; 3 схема; 4 нет снимка перед заменой; 5 несовпадение checksum/формата.
