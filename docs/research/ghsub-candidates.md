# Что из исследования Ленты уходит в ghsub, и как unagi и ghsub живут на одном сервере

Дата: 2026-10-12. Опирается на ghsub [ADR-006](https://github.com/losoph/ghsub/blob/main/docs/adr/ADR-006-email-aggregator-and-server-profile.md)
и на [lenta-research.md](lenta-research.md). Документ лежит в unagi, потому что вырос из его
исследования. В ghsub его стоит перенести как вход для ADR-007 и следующих.

## 0. Роли (решение владельца 2026-10-12)

| | **unagi** | **ghsub** |
|---|---|---|
| Суть | Telegram-бот: напоминания, закладки, дайджесты и **Лента** Telegram-каналов | Выборка ключевого **откуда угодно из онлайна** в почту |
| Источники | Только Telegram-каналы (MTProto-сессия, `channel_posts`) | GitHub, RSS/Atom/JSON Feed, сайты без RSS, Reddit/HN/YouTube, рассылки; Telegram — **только через контракт unagi** |
| Управление | Кнопки в боте, по запросу пользователя | Конфиг и расписание (cron), позже — онбординг |
| Выход | Сообщения в чат, Telegraph | Письмо (HTML + текст) |
| Почта | Текущая email-ветка дайджестов живёт как есть, новыми функциями не расширяется (кроме ссылок «Отписаться/Перенести», 12.10). **Лента на почту — не в unagi** | Всё почтовое: вёрстка, отбор, расписания писем, отписки |

## 1. Что не подходит Ленте и становится кандидатами в ghsub

Лента — это только Telegram-подписки и только Telegraph. Всё ниже — источники вне Telegram или
почтовые механики.

### 1.1 Новые источники

| # | Возможность | Откуда идея | Комментарий для ghsub |
|---|---|---|---|
| G1 | **RSS / Atom / JSON Feed** с условным GET (`ETag`, `If-Modified-Since`) | RSS-to-Telegram-Bot, flowerss-bot, rssbot (звёзды losoph); goeland, telekilogram | Первый источник после GitHub (ADR-006, п. 5). `feedparser`, не больше 2 запросов на хост, джиттер |
| G2 | **Сайты без RSS** | RSS-Bridge (9,3k★), damoeb/rss-proxy (1,9k★) — оба в звёздах losoph | Свой инстанс RSS-Bridge на aiqu или разбор HTML по CSS-селекторам. Публичным инстансам не доверять |
| G3 | **Площадки через RSSHub**: YouTube, Reddit, X, VK, Habr, VC | DIYgod/RSSHub; feedgrab (614★, звезда losoph) | Только свой инстанс (`RSSHUB_BASE_URL`). Feedgrab заточен под китайские площадки — брать идеи нормализации и метрик, а не код |
| G4 | **Изменения страниц** («что поменялось на странице») | Watched files в ghsub; dgtlmoon/changedetection.io | Обобщение текущих «отслеживаемых файлов» GitHub на любой URL: дифф выбранного блока страницы |
| G5 | **GitHub-релизы, Hugging Face, Reddit, X** с модерацией и недельным обзором | dacrimeblock/telegram-ai-feed-relay-bot (звезда losoph) | Релизы уже есть. HF-модели и датасеты — тот же тип «релиз» |
| G6 | **Почтовые рассылки** как источник | kill-the-newsletter | Could: отдельный ящик → парсинг писем |
| G7 | **Здоровье источников**: active / erroring / gone, одно сводное уведомление | yaf2m, simple-feed-reader | Без спама: один алерт на сломанные источники за прогон |
| G8 | **OPML** импорт и экспорт | walrss, RSStT | Перенос подписок из RSS-читалок |

### 1.2 Отбор ключевого из разнородных источников

| # | Возможность | Откуда | Комментарий |
|---|---|---|---|
| G9 | **Перцентиль внутри источника** вместо абсолютных чисел | email-digest.md §2.1, nyan | Звёзды, очки HN, апвоуты Reddit и просмотры несравнимы. Сравниваются перцентили за 30 дней |
| G10 | **Вес «частоты»: тема всплыла в нескольких источниках** | TrendRadar (`rank/frequency/hotness`, пресеты) | Пресеты «быстрые тренды / глубокие темы» на коллекцию |
| G11 | **Гравитация по времени** для «горячего» | Hacker News, Reddit hot | Для почты раз в неделю — слабая, для ежедневной — как у HN |
| G12 | **Ключевые слова include/exclude** на источник и коллекцию | TrendRadar `frequency_words.txt`, yaf2m, goeland | Дёшево, без ИИ |
| G13 | **ИИ-важность и сводка только для топ-N**; ссылки — непрозрачными ID | email-digest.md §2.4, SeanLF/news-digest | DeepSeek уже общий на aiqu. Защита от prompt-injection из чужих текстов |
| G14 | **Дедуп между источниками**: канонизация URL (без `utm_*`), `SequenceMatcher` по тексту | tg_digest, Telebrief | Одна история — один пункт со списком источников |

### 1.3 Почтовые механики

| # | Возможность | Комментарий |
|---|---|---|
| G15 | `List-Unsubscribe` + `List-Unsubscribe-Post: One-Click` | Требование Gmail/Yahoo. Нужен маленький HTTPS-эндпоинт за nginx aiqu; GET-ссылки прокликивают сканеры — подтверждение POST |

## 2. Как подружить проекты на одном сервере (aiqu, затем РФ-сервер)

### 2.1 Принципы

1. **Раздельные кодовые базы и хранилища** (ADR-006). Никакого чтения SQLite unagi из ghsub.
2. **Одна MTProto-сессия — один владелец: unagi.** ghsub не подключается к Telegram сам: два
   клиента на одной сессии из разных процессов Telegram воспринимает как подозрительную
   активность и может отозвать сессию. Telegram-контент попадает в ghsub только через контракт.
3. **Общее — только инфраструктура:** `/root/.msmtprc` (оба уже шлют через Brevo), ключ DeepSeek,
   `ops/common.sh` из tldw (замок, `send_mail`), `/etc/tldw/health.env`, мониторинг.
4. Общий Python-пакет (MIME, санитайзер HTML, клиент DeepSeek) — только когда дублирование
   реально мешает (ADR-006, п. 4).

### 2.2 Контракт выпуска unagi → ghsub (v1)

Один формат для дайджеста и Ленты: ghsub не различает, откуда пришёл выпуск, он его отбирает
(при необходимости), верстает и отправляет.

```json
{
  "schema_version": 1,
  "edition_id": "unagi:feed:<recipient>:<period>:<window_end>",
  "kind": "feed",                    // feed | digest
  "recipient": "<согласованный ID адресата, не user_id бота>",
  "period": "day",                   // day | week | month (для digest — daily/weekly/monthly)
  "window": {"from": "2026-10-11T07:00:00Z", "to": "2026-10-12T07:00:00Z"},
  "timezone": "Europe/Moscow",
  "title": "Лента за день · 12.10.2026",
  "telegraph_url": "https://telegra.ph/...",
  "items": [
    {
      "rank": 1, "score": 0.87,
      "source": {"type": "telegram", "channel": "durov", "title": "Durov's Channel", "tag": "Tech"},
      "post_id": 123, "published_at": "2026-10-12T05:10:00Z",
      "text": "полный текст", "link": "https://t.me/durov/123",
      "metrics": {"views": 120000, "forwards": 340, "reactions": 1200, "replies": 50},
      "also_in": ["channel_b", "channel_c"]
    }
  ]
}
```

- **Идемпотентность**: повторная передача того же `edition_id` не создаёт второго письма.
- **Транспорт на одном хосте — каталог-«почтовый ящик»**: unagi атомарно пишет
  `/var/lib/unagi-outbox/<edition_id>.json` (запись во временный файл + `rename`), ghsub забирает
  файл своим запуском или по systemd `.path`-юниту (отправка сразу, без ожидания cron) и кладёт
  квитанцию `<edition_id>.ack.json` (`delivered | failed`, время, ошибка) в
  `/var/lib/ghsub/acks/`. unagi при следующем цикле читает квитанции: «не ушло» → fallback
  в Telegram, как сейчас у email-дайджестов.
- Docker: unagi пишет в bind-mount каталога outbox, права `640`, владелец — группа ghsub.
- В контракт не входят секреты, настройки бота, внутренние ошибки и user_id.

### 2.3 Адресат и согласие

- Адрес уже подтверждён кодом в unagi (`/email`). В контракт идёт не адрес, а ID адресата.
  Таблица соответствия «ID → адрес» и флаг согласия передаются ghsub отдельно, один раз
  (файл `recipients.json` в том же outbox), чтобы письмо отправлял тот, кто отвечает за почту.
- Отписка из письма — в ghsub (G15), он же присылает unagi событие «адресат отписался» через
  квитанцию. unagi в ответ возвращает выпуск в Telegram.

### 2.4 Порядок переезда почты

1. **Сейчас (12.10):** email-дайджест unagi работает как есть. Лента — только Telegram/Telegraph.
2. **ghsub ADR-007** (многопользовательская основа) + G1 (RSS) — без участия unagi.
3. **Контракт v1** на обеих сторонах с тестами формата; unagi начинает писать в outbox
   параллельно со своей email-отправкой (dry-run: ghsub только проверяет и квитирует).
4. Переключение: email-периоды дайджеста и Лента «на почту» отправляет ghsub; email-ветка unagi
   (`email_digest.py`, SMTP) отключается после согласия пользователей.

### 2.5 Ресурсы и расписания

- Тяжёлые прогоны разнести по времени: дайджесты unagi — утро (07:00), ghsub — воскресенье
  07:00 сейчас. После переезда почты ghsub отправляет выпуски unagi по факту появления в outbox,
  без своего cron.
- Обе службы под одним мониторингом (tldw health): watchdog unagi уже шлёт админ-алерты,
  ghsub — через `send_mail`.
- Лимиты памяти: unagi `mem_limit 512m`. ghsub — короткоживущий процесс, на нагрузку не влияет.
