# Лента: исследование аналогов и ранжирования

Дата: 2026-10-12. Вход для спринта [2026-10-13-lenta-sprint.md](../sprint/2026-10-13-lenta-sprint.md).
Что из найденного не подходит Ленте (источники вне Telegram, почта) — в
[ghsub-candidates.md](ghsub-candidates.md).

**Лента** — ранжированная подборка постов из каналов, которые пользователь добавил вручную
(пересылкой поста или ссылкой, как для дайджеста). В отличие от дайджеста, у подписки Ленты нет
периодичности, а посты не группируются по каналам или папкам. Все каналы Ленты ранжируются одним
алгоритмом за выбранный период (день, неделя, месяц), в выпуск попадает до 50 постов, сверху —
то, что набрало наибольший **охват и пересылки**. Выпуск собирается по запросу пользователя и
показывается только страницей Telegraph.

## 2. Что нашли

### 2.1 Ближайшие по смыслу

| Проект | Что делает | Что берём в Ленту |
|---|---|---|
| [NyanNyanovich/nyan](https://github.com/NyanNyanovich/nyan) (330★, Python, рус.) | Автоагрегатор новостей из сотен каналов в канал-выпуск | Кластер одного сюжета из нескольких каналов. **Просмотры в час со сглаживанием выбросов** (`debiased_views / age`). Порог по **перцентилю** внутри набора, а не абсолютный. Флаг «важно» для свежего кластера, который быстро набирает просмотры. Минимум уникальных каналов в кластере (`min_channels`) |
| [sansan0/TrendRadar](https://github.com/sansan0/TrendRadar) (62,8k★) | Мониторинг горячего из многих площадок | Прозрачная формула: `0,6·место + 0,3·частота + 0,1·горячесть`, сумма весов = 1. **Пресеты**: «быстрые тренды» (место 0,8) и «глубокие темы» (частота 0,5) |
| [chernoyarova/tg_digest](https://github.com/chernoyarova/tg_digest) (звезда losoph) | Радар вакансий из папки каналов → статическая страница | **Теги — чипы на карточке.** Дедуп через `difflib.SequenceMatcher` → одна карточка «ещё в 3 каналах». Метка NEW для постов моложе суток |
| [belaytzev/Telebrief](https://github.com/belaytzev/Telebrief) (звезда losoph) | Дайджест каналов с ИИ-сводкой | `dedup_topics`: одна история — один пункт со списком источников |
| [alxyrgin/news-digest](https://github.com/alxyrgin/news-digest), [iusekarma/telegraph_daily](https://github.com/iusekarma/telegraph_daily) (звёзды losoph) | Длинный выпуск — одной страницей Telegraph | Подтверждают формат «страница Telegraph + короткое сообщение со ссылкой» |
| [sangaline/reverse-engineering-the-hacker-news-ranking-algorithm](https://github.com/sangaline/reverse-engineering-the-hacker-news-ranking-algorithm) | Реверс формулы HN | `(P−1)/(T+2)^1.8` — «гравитация» топит старое |
| [codesuki/go-trending](https://github.com/codesuki/go-trending) | «Trending at Instagram» | Тренд — отклонение текущей скорости от базовой линии; у нас это «×N к норме канала» |

### 2.2 Формулы-ориентиры

- **Hacker News**: `score = (P − 1) / (T + 2)^G`, `G = 1.8` ([разбор](https://www.righto.com/2013/11/how-hacker-news-ranking-really-works.html)).
  Хорошо для «сейчас», плохо для «картины недели»: время доминирует над охватом.
- **Reddit hot**: `log10(max(|s|, 1)) + sign(s) · t / 45000` ([вывод формулы](https://evanmiller.org/deriving-the-reddit-formula.html)).
  Логарифм: первые 10 голосов весят как следующие 100; каждые 12,5 ч дают ×10.
- **ERR** (вовлечённость по охвату) = реакции / охват × 100%. Ориентир для Telegram — 2–5%
  ([Unisender](https://www.unisender.com/ru/glossary/chto-takoe-err/), [Spark](https://spark.ru/startup/tg-pro/blog/331663/analitika-telegram-kanalov-kak-analizirovat-auditoriyu-reklamu-i-effektivnost-kontenta)).
  Официальных формул TGStat (ERR, индекс цитирования) в открытом доступе не нашли.
- **unagi сейчас** (`ranking.score_post`): пересылки относительно медианы канала (вес 0,40),
  просмотры с поправкой на «зрелость» (0,25), реакции (0,15), ответы (0,05), свежесть (0,15).
  Это ранжирование **внутри** канала — для дайджеста. Лента сравнивает посты **разных** каналов.

### 2.3 Что поддерживает Telegram API без лишних запросов

- `views`, `forwards`, `replies`, `reactions` приходят с сообщением Telethon (уже собираем, T3).
- **`messages.getMessagesViews(peer, id[], increment=false)`** возвращает просмотры, пересылки и
  ответы **до 100 постов за один запрос** без загрузки самих сообщений. Это дешёвое обновление
  метрик уже сохранённых постов перед сборкой Ленты. Реакции так не обновляются — для них хватит
  значения с последней загрузки.
- Охват канала (`participants_count`) кешируется в `channels` раз в сутки.

## 3. Выводы для Ленты

1. **Сравнивать разные каналы честно.** Абсолютный охват нужен (главное за день — то, что
   увидели больше всего людей), но только он отдаёт всю Ленту крупным каналам. Решение — смесь
   абсолютных и относительных сигналов, каждый приведён к **перцентилю внутри набора кандидатов**
   (как в nyan). Тогда веса сопоставимы и устойчивы к выбросам.
2. **Пересылки — главный сигнал вовлечения** (требование владельца). Берутся и абсолютное число,
   и доля от просмотров относительно нормы канала.
3. **Свежесть — слабый регулятор, масштабированный под период.** Для дня полураспад 12 ч, для
   недели 72 ч, для месяца 10 суток. Гравитация в стиле HN не подходит: «картина недели» должна
   показывать самое заметное за неделю, а не за последние часы.
4. **Один сюжет — одна карточка.** Если несколько каналов Ленты написали об одном, это сигнал
   важности (частота у TrendRadar, `min_channels` у nyan): карточка получает бонус и строку
   «также в: …».
5. **Разнообразие.** Мягкий штраф за повтор канала (`×0,85` за каждый следующий пост) и жёсткий
   потолок на канал, чтобы Лента была картиной дня, а не лентой одного крупного канала.
6. **Реклама.** Посты с маркировкой (`erid`, «Реклама», `#реклама`) отбрасываются до ранжирования:
   у рекламы бывают накрученные просмотры.
7. **Тег** — подпись у названия канала (чип, как в tg_digest), на порядок не влияет.
8. **Метрики должны быть свежими.** Пост, загруженный через час после публикации, хранит
   просмотры часового возраста. Перед сборкой — массовое обновление через `GetMessagesViewsRequest`.

Формула и параметры — в спринте, раздел «Алгоритм ранжирования».
