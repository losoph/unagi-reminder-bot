Рекомендации каналов Telegram показывает давно, лента по умолчанию — хронология.

## 2. Что вероятно в ранжировании (гипотезы, не факты)

- Сигналы, которые Telegram сам отдаёт в API и показывает в интерфейсе: просмотры, пересылки, реакции, комментарии, свежесть, частота публикаций канала, число Premium-подписчиков (отмечали для поиска каналов; SEO-блоги, 2023–2025).
- «Added» почти наверняка — хронология/группировка по выбранным каналам; персонализация — только в «For You».
- Утверждения про «апдейты алгоритма раз в 8–12 дней» и пр. — только маркетинговые блоги, не использовать.

## 3. Как это соотносится с нашей Лентой (feed_ranking.py, ranking.py)

У нас уже есть: пересылки-первыми относительно медианы канала, нормализация по каналу (медианы копятся от 3+ измеренных постов), свежесть, срезание рекламы, сюжеты из нескольких каналов, Telegraph-страница на день/неделю/месяц, доставка по расписанию в Telegram и на почту.

Чего у клиента, скорее всего, не будет (по крайней мере в бете): **периодические «выпуски» (день/неделя/месяц) с фиксированным временем и доставкой вне приложения (почта, Telegraph-страница, ссылка)**, **фильтр рекламы**, **сюжеты — склейка одной темы из разных каналов**, **выжимка «Коротко» и абсолютные даты**, работа **без Telegram-клиента** (почта) и **история выпусков**.

## 4. Идеи для дорожной карты (чтобы не дублировать клиент)

Принцип: **клиент — «читать сейчас, лента без конца»; unagi — «получить готовый выпуск в нужное время и там, где удобно».** Не конкурировать с бесконечной лентой и рекомендациями непоставленных каналов.

1. **Позиционирование «выпуск по расписанию»** — усиливать то, чего нет в клиенте: расписание (день/неделя/месяц), почта, Telegraph, архив выпусков. Сделано: собственное расписание Ленты и доставка на почту (PR 18.10).
2. **Не строить «For You»**: не рекомендовать неподписанные каналы и не вводить персональный бесконечный поток. Допустимо лишь «каналы, которых стоит ждать»: подсказка по каналам из папок Telegram (импорт), уже в бэклоге.
3. **Использовать ранжирование клиента как сигнал, а не копировать**: если Telegram отдаст ботам/MTProto реакции, число комментариев, признак «рекомендован» — добавить их как признаки в `feed_ranking.py` рядом с пересылками (без собственной «секретной формулы»); ориентир — наша нормализация по медиане канала.
4. **Темы вместо LV4-авто-тем**: если в клиенте появятся пользовательские темы/категории («Added»), то наш тег Ленты (`feed_subscriptions.tag`) сделать импортируемым из них и **не** строить собственные авто-темы (LV4-тематические разделы — заморозить до проверки).
5. **ИИ-сводка**: клиент получил ИИ-сводки постов; наша ценность — сводка *периода по нескольким каналам* и сюжеты. Дублирующую «сводку одного поста» не делать; блок «Главное» на странице периода — оставить только если отличается от клиентской сводки.
6. **Поиск**: глобальный поиск постов теперь платный/лимитный в клиенте — сохранённые запросы («алерт по ключевому слову») как расписанная доставка — уникальное для бота; в бэклоге «keyword-фильтры».
7. **Обучение ранжированию по 👍/👎**: вес в личных настройках, но только поверх нашего «выпуска»; клиентская лента этих сигналов не увидит.
8. **Мониторинг**: ручная проверка блога/релиз-нот перед письмом 24.10 вместо автоматического watcher (снят 18.10).
