UNAGI — СУББОТА 31.10: ПЕРЕЕЗД НА РОССИЙСКИЙ СЕРВЕР (письмо-напоминание, 11:00 МСК)
Письмо самодостаточно: его можно вставить в новую сессию Claude Code в репозитории unagi. Решение владельца 18.10: переезд сдвинут с 21–22.10 на «после 24.10, около 31.10».

1. ГОТОВО В РЕПОЗИТОРИИ
   - Шифрованный экспорт/проверка/восстановление БД: ops/aiqu/export_db.py (age), инструкция — ops/aiqu/README.md, раздел о переезде. Отказывает на пустой/чужой БД и при живом WAL.
   - Подготовка пользователя деплоя: ops/aiqu/setup_deploy_user.sh (решение владельца: пользователь deploy вместо root — ТОЛЬКО на новом сервере).
   - Деплой проверяет живость контейнера и метку версии; prod_check.sh показывает права процесса, диск, docker system df.

2. ПОРЯДОК (MTProto-сессия: в каждый момент ровно один работающий клиент)
   1) Новый сервер: Docker, OVPN-туннель до Telegram DC, пользователь deploy (setup_deploy_user.sh), клон репозитория, .env и msmtprc (секреты переносит владелец вручную).
   2) СЕТЕВОЙ KILL-SWITCH (критично, по ревью Argon 18.10): правила firewall, запрещающие процессам контейнера (uid 10001) выход к Telegram мимо tun0; проверить, что при остановленном туннеле бот НЕ подключается к Telegram с российского IP. Без этого — риск отзыва сессии.
   3) Старый сервер: docker compose stop (бот корректно завершается, WAL сбрасывается), финальный export_db.py.
   4) Копирование архива, verify и restore на новом; запуск; prod_check.sh с PROD_SSH=<новый хост>.
   5) GitHub: секреты HOST/USERNAME=deploy/SSH_KEY нового сервера; первый деплой — наблюдать.
   6) Старый сервер не удалять неделю: откат = остановить новый, запустить старый.

3. ОТКРЫТО ДО ПЕРЕЕЗДА: network_mode: host → bridge только после проверки маршрутов через туннель (можно уже на новом сервере); корректное завершение с чекпоинтом WAL (в работе после ревью Argon).
