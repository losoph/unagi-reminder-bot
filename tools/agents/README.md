# Монитор агентов

Набор переносимых утилит для запуска и наблюдения исполнителей agy и opencode из любого git-проекта. Коммиты локальные; push выполняет только владелец после проверки.

## Роли и worktree

- **Наблюдатель** задаёт задачу, следит за логами, проверяет каждый коммит и принимает решение о переходе к следующему этапу.
- **Исполнители** работают каждый в своём worktree, проверяют результат и коммитят.
- **Ревьюеры** получают отдельное detached-дерево и не меняют исходники.

Worktree по умолчанию размещаются в `~/dev-worktrees`, вне Google Drive и iCloud. Синхронизирующие облачные папки переименовывают конфликтующие файлы в `«(1)»` и могут ломать сокеты fsmonitor. Для нового дерева отключается `core.fsmonitor`.

```sh
tools/agents/worktree.sh new impl feature-branch main
tools/agents/worktree.sh review reviewer HEAD
tools/agents/worktree.sh rm reviewer
```

Путь можно переопределить через `AGENT_WORKTREES`. При запуске `rm` учитывайте незакоммиченные изменения: Git откажется удалять грязное дерево.

## Вкладки терминала

Пути и параметры в примерах ASCII; замените placeholders на пути без кириллицы.

```sh
AGY_LOG_DIR=.agy AGY_MODEL=gemini-3.8-flash-high AGY_PROXY="$HTTPS_PROXY" tools/agents/agy_supervise.sh brief.md '(TASK-1)' 6
tools/agents/agy_watch.sh follow
tools/agents/agy_watch.sh digest 600
tools/agents/oc_run.sh ../dev-worktrees/impl Tokenn/gpt-6.1-sol brief.md .agents/impl.ndjson impl
tools/agents/oc_run.sh ../dev-worktrees/reviewer Tokenn/gpt-6.1-sol review.md .agents/review.ndjson review --review
PERIOD=600 python3 tools/agents/oc_digest.py < .agents/impl.ndjson
tools/agents/route.sh opencode executor-complex 'Implement the requested feature'
tools/agents/usage.sh
```

`AGY_LOG_DIR` задаёт журнал agy, `AGY_MODEL` — модель, `AGY_PROXY` при наличии экспортируется в дочерний процесс как `HTTP_PROXY`/`HTTPS_PROXY` и варианты в нижнем регистре. В отдельных вкладках окружение наблюдателя может отсутствовать, поэтому задавайте прокси явно.

`--inline` кладёт текст брифа прямо в сообщение вместо вложения `-f`: короткие сверки (`oc_check.sh`) работают только так — `Tokenn/gpt-6.1-sol` содержимого вложения не получает (видит имя `brief.md`) и, если бриф запрещает читать файлы, отвечает «нет diff» (17.10: два прогона впустую). `OC_RUN_TIMEOUT` (секунды, по умолчанию 900) — предохранитель по времени: прогон без событий (зависший шлюз) прерывается кодом 142. Режим мышления Tokenn (панель: Min/Low/…) на зависания не влиял: тривиальный запрос при Low — 6 с; сверка контейнера с контекстом в сообщении — до минуты и ≈7 тыс. токенов.
`oc_run.sh` принимает `<worktree> <model> <brief.md> <log.ndjson> <title> [--review]`. Режим `--review` просит только анализировать и запрещает изменения. Команда передаёт краткое ASCII-сообщение: оно не зависит от кодировки оболочки и аргументов CLI. `--standalone` не подключает фоновый сервис opencode, который может не видеть ключ провайдера текущей оболочки и отвечать 401. После процесса в NDJSON записывается `run_end`; `oc_digest.py` печатает `OC RUN END`.

## Мониторы и протокол

- `agy_watch.sh follow` выводит завершённые шаги в реальном времени, чтения файлов группируются.
- `agy_watch.sh digest [SEC]` выдаёт агрегат действий и сразу подсвечивает риски и ошибки.
- `oc_digest.py` читает поток JSON/NDJSON, немедленно показывает ошибки, коммиты и конец прогона; `PERIOD` задаёт интервал сводки.
- `agy_watch.sh steps`, `reasoning`, `result`, `usage`, `id`, `status` дают детализацию последнего прогона.

Процесс: **коммит исполнителя → проверка наблюдателем → перекрёстное ревью → отдельный fix-коммит**. Не переходите к следующей задаче до оценки диффа. Наблюдение имеет три независимых слоя: git показывает **что**, дистиллят — **как**, журнал решений `docs/sprint/progress.md` — **почему**. Записи решений фиксируют выбор и компромисс, не дублируя список файлов и тестов.

Шаблоны заданий: `templates/review.md` и `templates/fix.md`. Перед запуском замените placeholders `<...>` конкретными значениями, перечислите проверяемые сценарии, ограничения на файлы и точные команды проверок. Не включайте секреты в бриф.

## Маршрутизация моделей и затраты

`routing.json` задаёт перечень кандидатов и статическую политику для видов `executor-complex`, `executor-ux`, `review`, `adversarial-review`, `docs`, `merge-audit`. `route.sh <agy|opencode|claude> <task-kind> [description]` выводит `model=... effort=... reason=...` и добавляет JSON-событие в `$AGENT_ROUTE_LOG` (по умолчанию `.agents/routes.ndjson`). Внешний `AGENT_ROUTER_CMD` получает JSON задачи через stdin и JSON-ответ; в окружении доступен `AGENT_ROUTE_CANDIDATES`.

### Выбор модели на задачу через Jev

Чтобы включить динамический выбор, задайте `OPENROUTER_API_KEY` (или `TYPESAFE_API_KEY`) и не устанавливайте `AGENT_ROUTER=static`. Доступны настройки `JEV_URL`, `JEV_MODEL`, `JEV_TIMEOUT` (10 секунд по умолчанию) и `JEV_MIN_CONFIDENCE` (0.4). Решение выдаётся в двух строках, включая `meta=` с вероятностями, уверенностью, стоимостью и задержкой. Например:

```sh
OPENROUTER_API_KEY="$OPENROUTER_API_KEY" tools/agents/route.sh opencode executor-complex 'Реализовать многофайловую задачу' --dry-run
```

Jev решает вопрос один раз на задачу, а не на каждый запрос к исполнителю: повторные вызовы исполнителя используют ту же выбранную модель, а кэширование промптов продолжает работать. При недоступности сервиса, низкой уверенности или рекомендации эскалации применяется неизменённая статическая политика; причина сохраняется как `fallback_reason`. `--dry-run` показывает результат и не пишет журнал маршрутов. Стоимость решений хранится отдельно в `meta.cost` и выводится `usage.sh` строкой `jev_decisions`.

Используйте только API и ключ OpenRouter. Сторонний сайт thejevai.com и опубликованные на нём адрес API/инструкции по ключам к этой интеграции не относятся; не отправляйте туда ключ OpenRouter. Стоимость одного решения зависит от тарифа и длины описания, обычно она мала, но каждое обращение оплачивается отдельно.

`usage.sh` суммирует доступные токены agy (`result.usage`) и opencode (`step_finish`), используя `$AGY_LOG_DIR/session.ndjson`, `$OC_LOG` и журнал маршрутов. Совпадение выбора модели с затратами выполняется по `title`; задавайте одинаковый title в маршрутизации и запуске, иначе выбранная модель будет `-`. Поддержка полей usage зависит от версии CLI и схемы его событий.

### Единая точка входа: `agents.sh` (для любых сессий)

Из любого проекта и любой сессии достаточно знать один путь — `<репозиторий>/tools/agents/agents.sh help`:

| Команда | Что делает |
|---|---|
| `status` | бюджеты opencode и dsh, наличие ключей (без значений), путь к `dsh`, жив ли веб-интерфейс harness, сводка Jev |
| `pick <kind>` | лестница исполнителей и выбранный: **dsh → agy → (opencode, только если вид задачи разрешён)**; пропущенные — с причиной |
| `run <agent> <kind> <worktree> <brief> <log> <title> [--review]` | `route.sh` (Jev) → `dsh_run.sh` / `oc_run.sh`; для opencode — только если модель и эффорт выбрал Jev |
| `check <agent\|auto> <title> "<вопрос>" <файл-контекст>` | короткая сверка: вопрос + ≤24 КБ контекста, без инструментов, ответ ≤200 слов |
| `watch <dsh\|opencode\|agy> <log>` | живой монитор: ошибки, коммиты, красные тесты, тревоги (`git push`, `rm -rf`, `.env`), итог прогона и расход токенов |
| `route <agent> <kind> "<описание>"` | только выбор модели и эффорта |
| `report` | что решил Jev, откаты на статику, стоимость решений |

Приоритет экономии токенов (владелец, 16.10): **opencode > deepseek > Jev > Claude > agy** — чем левее, тем бережнее. Отсюда лестница исполнителей;
какие виды задач вообще допускаются к opencode, решает `executor_policy.opencode_allowed` (по умолчанию — никакие).

### DeepSeek Harness (`dsh`)

Исполнитель вместо opencode для задач реализации, правок и ревью. Бинарник ищется так: `$DSH_BIN` → `dsh` в PATH → самый свежий `~/.npm/_npx/*/node_modules/.bin/dsh`
(так он стоит, если запущен `npx dsh web`; веб-интерфейс — `http://127.0.0.1:3080`, без авторизации отвечает 401). Ключ DeepSeek хранит сам dsh в `~/.dsh/.credentials.yaml`
(скрипты его не читают). Прогон — `dsh --profile headless --json -`, задание со stdin, рабочий каталог = cwd (worktree).

- `dsh_run.sh <worktree> <brief> <log> <title> [--review] [--model deepseek-flash|deepseek-v4-pro] [--effort off|low|high|max]` — лента в терминал, NDJSON в журнал, бюджет, итоговая строка токенов.
  Модель и эффорт задаются одноразовым патчем профиля (`--patch`, флаг лаунчера — **до** `--json`), `~/.dsh` не правится. `--review` — только инструкция «ТОЛЬКО ЧТЕНИЕ», изоляции нет.
- Модели: **DeepSeek V4.1 Flash** (`deepseek-flash`, основная) и **DeepSeek V4 Pro** (`deepseek-v4-pro`, только текст). Эффорт: **Off / Low / High / Max** (`reasoningEffort`).
- Токены: usage приходит в каждом событии `status/step_end` (`inputTokens`, `outputTokens`, `cacheReadTokens`). У DeepSeek работает кеш префикса — повторные шаги агента почти бесплатны.
  В лимит бюджета идут новые входные + выходные, кеш пишется отдельно (`cache_read`).
- **Калибровка 16.10.2026** (сверено с дашбордом DeepSeek: `deepseek-v4-pro` 15 039 токенов = мой журнал точно; `deepseek-flash` 87 754 против ≈87 226 по журналу — разницу дают служебные запросы заголовков сессий):

| Прогон (ревью ядра T24c, ≈9 КБ контекста) | Шагов | Новых входных | Выходных | Из кеша | Время |
|---|---|---|---|---|---|
| flash, эффорт high (по умолчанию) | 1 | 7 656 | 4 117 | 384 | 26 с |
| flash, эффорт high, повтор того же запроса | 1 | 7 605 | 12 428 | 384 | ~60 с |
| flash, эффорт off | 1 | 2 767 | 403 | 5 248 | 7 с |
| v4-pro, эффорт low | 1 | 8 025 | 7 014 | 0 | 54 с |
| flash, агентная задача (прочитать, записать, проверить) | 4 | 5 857 | 251 | 17 536 | 10 с |

  Выводы: выпуск при `high` вариативен до 3×; `off` в 4 раза дешевле, но даёт домыслы; `v4-pro` на ревью не дал выигрыша в качестве. `max` не измерен.

### Jev: модель и эффорт для каждого агента

`route.sh <agent> <kind> "<описание>"` — Jev выбирает **один раз на задачу** модель и эффорт; набор уровней у каждого агента свой (`routing.json` → `efforts`, описания для Jev — `effort_descriptions`,
в них — замеры из таблицы выше): dsh — `off|low|high|max`, остальные — `low|medium|high`. Ответ Jev с уровнем, которого у агента нет, отклоняется (откат на статическую политику, причина — в `fallback=`).
Виды задач (`kind`): `executor-complex`, `executor-ux`, `review`, `adversarial-review`, `docs`, `merge-audit`, `short-check`.

- **dsh** — модель и эффорт применяются патчем профиля. **opencode** — эффорт применяется как вариант модели `provider/model#low|medium|high`; варианты (`reasoningEffort`) должны быть описаны
  в `~/.config/opencode/opencode.json` — `tools/agents/oc_variants.py status|apply` (правит только `variants` у кандидатов, делает резервную копию; opencode 2.x не читает `OPENCODE_CONFIG*`).
  Без определённого варианта `oc_run.sh --effort` отказывает (код 5): суффикс молча ничего бы не менял. **Влияние эффорта на стороне шлюза Tokenn не проверялось** (чтобы не тратить токены opencode):
  проверить по полю `reasoning` в `step_finish` при первом запуске через Jev.
- **opencode запускается только с решением Jev** (`agents.sh run opencode` без него — код 4). Для Claude (наблюдателя) и agy эффорт не принципиален: `route.sh` только рекомендует.
- Решение принимает Jev, а не я: нет ключа → честный откат на статическую политику (dsh, agy) или отказ (opencode); это видно в `agents.sh status` и `report`.

### Режим экономии токенов opencode (с 16.10.2026)

У opencode каждый шаг агента заново присылает весь контекст, кеш не используется: два прогона T24c потратили ~8,9 млн входных токенов
(143 шага по 60–90 тыс.). Поэтому opencode — только **короткие сверки**, реализация и ревью крупных диффов — agy и наблюдатель.

- **Бюджет:** `budget.json` — opencode — 5 000 000 токенов на спринт/сессию (`sprint_tokens`, лимит подтверждён владельцем 16.10 после пополнения), 1 000 000 на прогон (`run_tokens`); dsh — 3 000 000 / 400 000 (стартовые значения, подстраиваются). Считается input + output + reasoning
  из `step_finish`. Журнал — `~/.config/agent-tools/oc-ledger.ndjson` (общий для всех worktree); статус — `tools/agents/oc_budget.py status`.
  Новый спринт — новая метка `sprint` в `budget.json`; расход прошлых записей в остаток не входит (`--reference` — только справочно).
- **Предохранитель:** `oc_run.sh` не стартует при пустом остатке (код 3) и обрывает прогон при превышении лимита прогона или спринта:
  пишет `budget_exceeded` в NDJSON, останавливает `opencode run` явно (SIGPIPE агент может проигнорировать). `OC_BUDGET=off` — только осознанно.
- **Короткая сверка:** `tools/agents/oc_check.sh <метка> "<вопрос>" <файл-контекст>` — вопрос и до 24 КБ контекста (например, `git diff` одной функции) в одном
  запросе, без чтения файлов и инструментов; ответ ≤ 200 слов. Для всего остального — `route.sh agy …`.

### Простые решения через Jev (`decide.sh`)

Тот же сервис решает не только «какая модель», но и ключевые простые развилки процесса: закрытый список вариантов, уверенность, эскалация к человеку.

```sh
tools/agents/decide.sh "Влить T24c в main?" merge="ревью чистое, тесты зелёные" fix="есть подтверждённые дефекты" hold="не хватает данных" \
  --default hold --context-file review.txt --title T24c
```

Ответ: `choice=<вариант|ASK_HUMAN> source=jev|default|human confidence=…`, затем `fallback=…` и `meta=…`. Код выхода: `0` — решено, `10` — решает человек, `2` — неверный вызов. Журнал — `.agents/decisions.ndjson`, суммарная стоимость — строка `decide` в `usage.sh`.

- Порог уверенности — `JEV_DECIDE_MIN_CONFIDENCE` (0.7, строже, чем у выбора модели): ниже порога берётся `--default`, а без него решает человек. Эскалация Jev (`noul` ≥ 0.5) всегда отдаёт решение человеку, даже при `--default`.
- Нет ключа или сеть недоступна — тот же путь отката, сеть не трогается.
- Годится для: «влить/вернуть автору/ждать» после ревью, «находка настоящая или ложная», «переходить к следующей задаче». **Не годится для необратимого:** push, откат прода, удаление данных остаются за наблюдателем и владельцем по `docs/HANDOFF.md` — Jev там только советует.
- В запрос уходят вопрос, варианты и `--context-file` (до 32 KiB); строки, похожие на ключи (`sk-…`, `Bearer …`, `…KEY=…`), заменяются на `[REDACTED]`. Секреты и персональные данные в контекст не кладите.

### Ключи агентов

Вкладки терминала не наследуют окружение, а `~/.zshrc` скрипты не читают. `route.sh` и `decide.sh` берут `OPENROUTER_API_KEY` (или `TYPESAFE_API_KEY`) из окружения, а если переменная не задана вовсе — из файла `~/.config/agent-tools/env` (путь меняется `AGENT_ENV_FILE`). Файл вне репозитория, права `0600`, строки `OPENROUTER_API_KEY=…`; он не выполняется как скрипт, разбираются только строки `ИМЯ=значение`. Ключ провайдера opencode (`Tokenn`) хранится в собственном `~/.config/opencode/opencode.json`.

## Подводные камни

- Для agy используется `zsh -ic`, чтобы загрузить алиасы/параметры из `~/.zshrc`; скрипт не читает и не сохраняет секреты сам.
- Вкладки терминала не наследуют переменные наблюдателя. Явно задавайте `AGY_PROXY`; без прокси Gemini может ответить `User location is not supported`.
- Избегайте кириллицы в путях worktree и логов: отдельные CLI и shell-расширения некорректно обрабатывают такие пути.
- Супервизор без `AGY_KEEP_TREE=1` сохраняет tracked diff и очищает дерево: `git clean` удаляет все неотслеживаемые файлы, кроме каталога логов. Не держите там данные; включение `AGY_KEEP_TREE=1` оставляет правки первой попытки.
- Логи могут содержать содержимое задач и ответов; выбирайте расположение и права доступа осознанно.

## Окружение исполнителей

Исполнителям запрещено ставить пакеты (`pip install` и т. п.): тесты и линтер — только из venv
проекта тех же версий, что в CI. 14.10 opencode без спроса поставил ~28 пакетов в системный
Python и проверял ruff другой версии — это правило в шаблонах `templates/*.md`. Команды, ждущие
stdin (`cat > file` без here-doc), вешают прогон агента на десятки минут — файлы только инструментом.

## Бомбы замедленного действия в тестах

`tools/agents/time_shift_tests.sh` прогоняет набор тестов со сдвинутыми часами (libfaketime:
+1d, +7d, +30d, +365d, -30d). Тест, падающий только при сдвиге, сравнивает жёсткую дату с
реальным «сейчас» и однажды сломает CI сам по себе. Запускать перед слиянием веток и перед
деплоем: `PYTHON=~/.venvs/unagi/bin/python tools/agents/time_shift_tests.sh`.
